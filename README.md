# harbor-kit

目标：在新的 Debian VPS 上，使用官方 Snell、ShadowTLS 和受信软件源中的
Nginx，完成自有域名 HTTPS 环境的部署与 SSH 中文菜单管理。

开发版源码仓库：[Shennai1/harbor-kit](https://github.com/Shennai1/harbor-kit)。内部命令仍为 `snellctl`。
尚无正式版本或经过整机验收的一键远程安装命令；公开源码不等于正式发布。
当前代码实现只读环境/依赖预检查、官方固定版本下载校验、中文菜单、配置模板和独立测试目录中的文件写入/恢复。
显式选择的 **`install --experimental` 新机向导会修改系统，仍属实验功能**。
默认菜单仍只读；不应在现有正常使用的节点上试装，也不应手动调用内部接口。
新增 `resume --experimental`，仅接续本机验收及续期演练完成、尚未开始公网启用的阶段。
新增 `rotate-key --experimental`，单独更换本工具已完成节点的 Snell 或 ShadowTLS 密钥。
两项分别更换的正常路径及随后正常重启恢复已有用户实测通过反馈；仍属实验功能。
新增 `change-port --experimental`，更换本工具已完成节点的 IPv4 TCP 公网入口。
低/高端口双向更换及换回后的正常重启恢复已有用户实测通过反馈；仍属实验功能。
新增 `change-token --experimental`，单独更换 Cloudflare API Token，执行两次 DNS 演练并恢复自动续期；尚待实机验收。
首次 Token 更换实测未完成，新增 `diagnose-token --experimental` 仅对尚未替换的候选执行单次诊断；不恢复或提交更换。
独立诊断出现 TXT 写入认证失败，用户确认候选原为 DNS 读取权限；修正后可用 `--after-permission-fix` 单次复测，仍不提交更换。
权限修正后的候选复测及 `resume-token --experimental` 受限接续已实机通过，正式路径演练、续期恢复及节点使用正常。
新增 `change-domain --experimental`，参数化更换域名、独立凭据和证书；跨区域更换正常流程及正常重启已取得用户实测反馈。
升级、通用系统变更恢复和卸载入口尚未实现。

手工部署基线已由用户在 Debian 13 / amd64 上验证：Snell 5.0.1 + ShadowTLS 0.2.25
（协议 v3）+ 本机 Nginx + Certbot DNS-01，IPv4 节点可用性、实际使用、
模拟续期及关机再开机后的恢复均已通过。
另有一轮实验安装由用户实测：在 SSH 断线后，经核查使用一次性命令接续，
新节点实际使用及正常重启恢复通过；不能据此宣称无需人工接续的完整安装通过。
本次菜单接续入口已通过本地测试，尚待独立实机验证；真实到期轮换仍未测。
同一测试环境随后分别验证了 Snell PSK、ShadowTLS 密码更换，用户反馈更新客户端配置后正常。
两项更换后的正常重启检查通过，服务、UFW、监听及续期定时器恢复，用户反馈节点正常。
实测通过不包含强制断电、失败恢复、全量负向认证或其他平台；详见[密钥轮换实测范围](docs/key-rotation.md#已取得的实测证据)。
随后公网端口双向更换及正常重启也取得用户通过反馈，详见[端口更换实测范围](docs/port-change.md#已取得的实测证据)。

## 已确定的范围

- 面向新机部署，不迁移第三方脚本创建的旧节点。
- SSH 中文菜单；节点管理与域名、证书管理分开。
- 每台部署生成新的节点密钥；运行所必需的凭据保留在受限文件中。
- 使用实际服务配置作为依据，不另外长期保存一份含密钥的完整配置数据库。
- Snell、ShadowTLS、Nginx、证书客户端和管理工具分别更新。
- 证书自动续期；协议大版本升级由用户选择；支持操作检查和失败恢复。
- 诊断报告按需生成、脱敏，不上传遥测或凭据。

实施顺序和验收要求见 [通用路线图](docs/roadmap.md)，
组件边界见 [设计约定](docs/design.md)。
私人历史笔记、运行配置和凭据不属于公开仓库内容。

可以从仓库下载源码，不需要把 GitHub Token 放到 VPS。当前只建议下载后进行只读检查，
不要在正常使用的旧节点直接启动实验安装。下载说明及代码校验边界见 [源码交付](docs/source-delivery.md)。
仓库名称不代表用途保密，公开代码可被任何人查看。项目尚未选择开源许可证；
不重新分发 Snell/ShadowTLS 二进制，其下载来源和各自许可保持独立。

## 当前可运行的命令

需要 Python 3.11 或以上。在项目目录运行：

```bash
python3 -m snellctl doctor
python3 -m snellctl doctor --json
python3 -m snellctl menu
python3 -m snellctl install-status --json
python3 -m snellctl cleanup-plan --json
python3 -m snellctl plan --domain node.example.net
python3 -m snellctl plan --domain node.example.net --node second --public-port 24443 --snell-port 32001 --tls-port 32443 --json
python3 -m snellctl artifacts list
python3 -m snellctl preflight --domain node.example.net
python3 -m unittest discover -s tests -v
```

`doctor` 不需要联网，不请求 sudo，不安装软件、不修改防火墙、不重启服务。
默认只向终端输出；`--json` 也不会自动保存文件。
无权限读取某项状态时标记为“未知”，不会据此判断安全。

交互终端中不带子命令也会进入中文菜单。默认包含环境检查、部署计划预览、安装阶段记录、需确认的 Surge 配置显示、清理前只读盘点和退出。
显式使用 `menu --experimental` 才显示新机安装、菜单 7 的受限接续、菜单 8 的单项密钥更换、菜单 9 的公网端口更换、菜单 10 的 CF Token 更换和菜单 11 的域名更换。
确认统一使用 `[y/n]`，默认取消，仅 `y`/`Y` 继续；不会再要求输入中文确认词，操作目标及风险仍会明确显示。
安装、条款、签发、续期、独立 SSH 等确认环节分别保留，不合并或自动回答；新提示尚待实机验证。
不显示尚未实现的升级或卸载选项。非交互调用须明确指定只读/沙盒等子命令，变更向导拒绝非交互输入。

`plan` 是离线预览，可在开发机器上使用，不检查当前系统、DNS、文件归属或端口占用，
不生成密钥、不读取 Token，不写入部署配置、不执行系统管理命令。输出包含用户主动输入的域名和拟用路径，
不是完全脱敏的诊断报告；退出码 0 仅表示输入通过语法校验并完成预览，不表示可以安装。
三个端口的默认值仅为建议，均可替换；两个后端保持回环监听。

内存模板包含 Snell INI、ShadowTLS JSON、独立 Nginx 站点、两个 systemd unit 和限定证书的续期钩子。
模板接收已提供的独立密钥，重复渲染不会重新生成密钥；计划预览不输出含密钥模板。
只有独立的 `client` 操作在用户确认后显示既有节点的客户端秘密。
候选文件仍含明文秘密，不能把隐藏对象 repr 当成加密；沙盒写入器已加入权限、归属、并发锁和恢复检查，
不能据此宣称真实系统的安装或恢复已经通过验收。

## 离线写入演练

新增 `sandbox init/prepare/status/recover`，只操作明确初始化的独立测试目录，
没有真实系统根目录写入开关。重复 prepare 不换密钥；存在同名文件、外部修改或未完成操作时停止。
恢复可选择继续或取消；已经提交的节点不会被取消命令当成卸载对象。
详细命令、敏感文件处理、恢复边界和限制见 [候选配置写入与恢复](docs/storage.md)。

本地测试覆盖真实子进程中断恢复、跨进程锁、完整沙盒命令试运行、下载校验失败处理、
准备/激活/公网启用失败路径、规则增量检查、真实本机 TLS、向导串联、伪终端隐藏输入及受控客户端配置显示。
另覆盖受限接续的阶段限制、现场复查、确认期间变化及重复操作拒绝。
密钥更换测试覆盖单项变更、确认后复查、中断/失败保留记录、导出阻断与秘密不泄露。
端口更换测试覆盖低/高端口权限转换、UFW 精确增删、SSH/IPv6 保持、秘密不变及不确定结果保留现场。
Token 更换测试覆盖候选及固定路径的两次演练、定时任务暂停/恢复、并发及配置漂移拒绝、失败保留和凭据不泄露。
域名更换测试覆盖独立证书/凭据、重复更换未使用域名、后续 Token/密钥/端口管理，以及阶段失败和配置漂移。
确认提示测试覆盖默认取消、仅 ASCII y/Y 放行、终端中断及目标信息保留。
这些本地测试不替代 Debian 实机或断电验收；已取得的用户实测范围见上文。

## 下载与预检查

压缩包和 ELF 架构，只保存不可执行的暂存文件，不安装。已实际重新下载两个文件并通过校验。
指纹来自此前手工测试，不能称为上游签名认证；不自动升级到新的协议大版本。

`preflight` 检查新机冲突和软件包依赖，只模拟 APT 安装，不刷新索引、不修改防火墙。
目前只接入 Debian 13 / amd64；返回成功也不代表可以开始安装。
详细用法和剩余条件见 [官方文件暂存与新机预检查](docs/downloads-and-preflight.md)。

## 受限中断接续

`resume --experimental` 或实验菜单 7 只处理前六阶段已有完成记录、
自动续期启用和公网开放均未开始的 `main` 节点，不是通用重试或修复命令。
用户重新输入原域名和四个实际端口，不要求重新提供 Token 或节点密钥。
先在锁内只读核对配置归属、证书、运行服务、监听、软件包版本和防火墙，
再分别确认自动续期、独立 SSH 登录和公网开放；执行前在锁内重新检查。
已完成节点、未完成意图、状态损坏、服务已停止或外部改动均停止，不清理或绕过保护。
不会下载、重装或重跑初次签发；正式续期任务可能执行到期续签。
当前已正常工作的节点不需要运行该入口。边界与用法见[受限接续说明](docs/install-wizard.md#受限接续)。

## 客户端配置

本工具完成部署的新节点，可在部署主机运行 `python3 -m snellctl client`，或选择普通菜单的 5。
输入公网 IPv4 并明确确认后，读取已登记且未改动的磁盘配置，显示一整行 Surge 节点声明。
不换密钥、不另存配置副本、不读取 CF Token/证书私钥、不执行系统命令或联网。
显示含明文密钥，不是脱敏诊断，终端或录屏可能保留内容；不要贴回对话。
导出成功不代表当前服务健康或外网可达。详见 [客户端配置说明](docs/client-export.md)。
自动安装的验证顺序和现阶段证据边界见 [新机实测清单](docs/new-host-acceptance.md)。

## 单项密钥更换

`rotate-key --experimental` 或实验菜单 8 只更换所选的 Snell PSK 或 ShadowTLS 密码。
读取本工具已完成节点的实际参数，确认独立 SSH 和更换目标后，重新核查并生成新的随机密钥。
成功时只重启所选组件，更新当前归属记录；不改域名、证书、CF Token、端口或防火墙。
不显示或备份旧密钥；新配置由用户另行通过 `client` 确认显示。
失败会尝试停用入口并保留待核查标记，阻止重试和导出；没有自动回退或通用中断恢复。
已取得两项分别更换后的客户端正常反馈及正常重启恢复证据；每台部署仍需独立验收。
故障恢复和菜单路由尚未实机验证。详见 [密钥更换与失败边界](docs/key-rotation.md)。

## 公网端口更换

`change-port --experimental` 或实验菜单 9 更换 IPv4 TCP 公网入口，保留 SSH、密钥、域名、证书和本机后端端口。
在锁内检查现有部署和新端口占用，独立 SSH 及目标端口确认后重新检查。
只修改 ShadowTLS 监听和必要的低端口绑定权限，添加新 IPv4 TCP 规则；新入口本机检查通过后删除本工具的旧规则。
不清空 UFW、不自动调整云安全组；客户端必须使用新端口。失败保留现场并尝试停止、禁用入口，不自动回退。
有未完成的端口更换标记时拒绝导出和后续变更。双向更换及正常重启已有用户实测通过反馈，
菜单路由和失败恢复仍未实机验证，详见 [端口更换与验收边界](docs/port-change.md)。

## Cloudflare Token 更换

`change-token --experimental` 或实验菜单 10 只更换当前完整受管节点的 CF API Token。
先创建同一区域 DNS 编辑权限的新令牌，保留旧令牌；终端隐藏输入，不接受明文参数。
程序暂停定时续期，用候选凭据完成 DNS 演练后替换固定凭据文件，再通过固定路径演练并核对 Nginx 重载。
成功后恢复自动续期，不改节点密钥、端口、域名、UFW 或 Surge；不强制重新签发正式证书。
失败保留待核查标记并尝试禁用自动续期，不停用节点，不自动回退；节点可用不代表续期正常。
正常不中断路径仍待实机验收；权限修正后受限接续的正式路径演练和续期恢复已有用户通过反馈。
旧令牌需在确认不再使用后由用户撤销。详见 [Token 更换与中断边界](docs/token-change.md)。

更换失败且正式凭据尚未替换时，可经只读核查与单独确认运行 `diagnose-token --experimental`。
已有完整 TXT 写入认证失败记录、同一令牌已修正云端权限时，可加 `--after-permission-fix` 执行一次复测；
保留原诊断，不重新输入令牌、不自动恢复续期，不提供反复重试。详见 [Token 更换](docs/token-change.md)。
权限复测成功且正式凭据尚未替换时，可经独立确认运行 `resume-token --experimental`：
替换凭据后验证正式路径，成功才恢复续期并清理候选/意图；不是通用失败恢复，不自动重试或回退。
诊断与接续均保存脱敏报告及 root-only 原始日志；不允许通过删除记录反复执行。
诊断通过不等于更换完成；受限接续已取得实机更换完成及原客户端正常使用反馈，真实到期轮换未测。

## 域名与证书更换

`change-domain --experimental` 或实验菜单 11 从当前受管配置读取节点参数，交互输入新完整域名和对应区域 DNS 编辑 Token。
先保留旧节点配置，验证并签发独立新证书，再重载 Nginx、检查新 SNI、执行永久凭据路径续期演练和恢复定时器。
不修改密钥、端口或 SSH/UFW，不要求两个域名属于同一区域；成功后更新客户端 SNI。
旧证书与原凭据保留，受管定时器只续期新证书；新凭据使用按域名分隔的永久路径。
后续 Token、密钥、端口管理与再次更换未使用域名已纳入本地测试，不写死测试域名或端口。
失败保留待核查记录，不自动回退或重试；尚无域名中断恢复，成功更换后的旧资源可另行核查并确认清理。
正常流程、客户端新 SNI 和正常重启已有用户实测反馈；失败恢复及其他平台仍未验收，详见 [域名更换与失败边界](docs/domain-change.md)。

## 清理前盘点

`domain-inventory --json` 或普通菜单 12 新增现用/保留证书与凭据的匿名引用报告。
它不读取 CF Token 或证书私钥内容，不联网、不执行系统命令、不写入或清理资源。
有限盘点完成不等于无人引用或可以删除，详见 [域名资源只读盘点](docs/domain-inventory.md)。

`retired-domain-plan` 或普通菜单 13 进一步确认一个真实旧域名，核对现用节点健康、
历史线索和旧凭据共享引用；仍没有删除入口。早期历史记录不完整，不自动认领旧文件。
详见 [旧域名清理预检查](docs/retired-domain-plan.md)。

`clean-retired-domain --experimental` 或实验菜单 14 另行确认归属与不可撤销的本机删除。
重新核查后暂停续期，用 Certbot 删除指定旧证书组/续期文件，再删除独立旧本机凭据，成功才恢复续期。
不改现用节点、SSH/UFW，不撤销 CF Token 或证书，不删除 DNS、ACME 账户、软件包和历史日志。
失败可能部分删除并保持续期暂停，保留标记且不自动回退或重试；尚待实机验收。
不是通用卸载器，也不会安装快捷入口，详见 [旧域名资源清理](docs/retired-domain-cleanup.md)。

`cleanup-plan` 或菜单 6 只读检查 main 的约定路径、服务、监听和共享目录计数，报告不含秘密。
没有安装器记录的手工节点不会被自动认领；有历史记录也不代表已核实当前归属。
不读取秘密配置、不停止服务、不删除文件、不修改 UFW、不卸载软件包。
这是复用测试机之前的准备，不是卸载器。详见 [只读盘点与清理边界](docs/cleanup-inventory.md)。

## 平台与版本

Nginx 模板可区分新旧 HTTP/2 语法，菜单预览默认使用手工基线的 1.26.3 语法。
开发时可用 `plan --nginx-version 1.22.1` 预览旧语法；这不是安全版本选择或安装指令。
真正安装时必须根据目标机实际安装版本选择语法、执行 nginx -t，并检查 Debian 软件包补丁状态。

计划部署平台是 Debian 12/13，x86_64/ARM64。其他系统上只报告平台不受支持，
不会尝试执行 Linux 管理命令；离线 `plan` 不受此限制。实机验收当前仅覆盖 Debian 13 / amd64 / IPv4 TCP。

`doctor` 退出码：`0` 表示此次检查完成且未出现需注意项，`1` 表示存在需注意或未知项，
`2` 表示平台不支持。这些返回值都不代表外网连通性或安全审计通过。

## 当前阶段的限制

- 有公开开发源码和实验版新机安装入口，但没有正式发布版、完整维护菜单或一键远程安装命令。
- 开发测试没有访问实际 VPS、Cloudflare 账户或 ACME 服务；上述实机结果来自用户手工操作和反馈。
  真正运行实验安装向导会安装系统组件、使用凭据访问 Cloudflare 并联系 ACME。
- 自动测试覆盖参数校验、模板内容、秘密输出限制、命令分派、菜单及只读检查，不代替目标机的 Nginx/systemd 运行验收。
- 已实现沙盒文件事务、下载验证、有限新机预检查及准备、激活、公网启用的交互串联；
  首轮实测使用过人工接续，完整向导和新菜单接续入口仍待复测。
  已加入受控客户端配置显示、受限接续、实验性单项密钥、公网端口、CF Token 及域名更换。
  Token 权限修正后的受限接续、跨区域域名更换正常流程及正常重启已取得用户实测反馈。
  组件更新、通用恢复或卸载尚未完成。
- IPv6、普通 UDP、QUIC Proxy Mode、Debian 12、ARM64 尚未实机验收；专门的错误密钥矩阵未测。
  轮换后旧配置失效是用户观察到的结果，不代替全量负向认证验证。
- 只读检查命令不刷新 APT 索引，也不判断最新安全补丁；实验安装会刷新/安装，接续不会重装或更新组件。
