# 受控更新的内部基础

当前没有可供用户运行的升级入口。内部基础包括范围约束、包下载校验、维护启动保护、
一次性后台提交、只读状态观察、安装后验收/恢复，以及串联这些步骤的内部协调器和受限重连接续。
现已增加包内容审查材料和分阶段确认的内部接口，以及独立的材料收集命令；
材料命令不执行安全审核或安装，实际升级的用户审查流程、CLI 和菜单仍未开放。
不能据此手动创建服务、运行 APT 或修改归属记录；模板和缓存本身不是执行授权。
内部保护和提交接口具有系统写入及停机能力，不是可单独使用的管理命令。

## 范围约束

`packagepolicy.revision_scope()` 处理本轮核对的安装状态、四项直接组件候选、完整模拟动作、
官方索引版本集合。调用者仍须证明这些输入来自刚完成的持锁检查，不能从历史报告导入。
函数返回不可变的变更列表，不保存文件。没有变更时返回空列表，不建立升级任务。

- 仅考虑既有 `ca-certificates`、`nginx`、`nginx-common`、`certbot`、`python3-certbot`、
  `python3-acme`、`python3-certbot-dns-cloudflare`、`python3-cloudflare` 的受限范围。
  列入范围不等于已经允许它们升级，来源、内容、依赖和维护脚本仍需后续审核。
- 拒绝新增软件包、其他依赖、架构切换、hold 变化、原版本不符、重复动作及候选不一致。
  SSH、UFW、内核和不相关组件不纳入更新；不解除原有 hold。
- 只允许 epoch 和上游版本文本相同的 Debian 修订变更，使用 `dpkg --compare-versions`
  判断新旧顺序，不采用字符串或普通语义版本比较；拒绝降级和同版重装。
  原生包没有 `-revision` 分界，例如 `ca-certificates` 的日期版本变化，不推定为修订升级，
  暂时要求独立审核。跨上游版本包括常规补丁版本也不在当前边界内。
- `nginx` 与 `nginx-common` 的原版本和最终版本必须对应；这不能替代 Nginx 模块兼容性检查。

这些是范围筛选，不是包签名验证、漏洞判断、完整执行方案或授权机制。

## 后台任务模板

现有通用命令适配器会在等待超时或中断时终止子进程。因此不能直接复用它执行真实升级。
实际包操作的内部设计采用唯一编号的 systemd oneshot 服务，交互终端只提交一次并观察状态。
`packagejob.JobSpec.unit_bytes()` 仅生成模板字节；写入及提交由独立内部接口处理。

模板固定以下约束：

- `Type=oneshot`、`RemainAfterExit=yes`、`Restart=no`，无启动时间上限，且没有开机启动段。
- 固定、受限的包名和完整目标版本；不接受命令、环境、URL 或文件路径参数。
- 独立进程环境，APT 不再下载包，不允许删除，只请求升级现有指定包。
  这些 APT 标志仍不能单独保证依赖完全不变，执行前须重新核对完整方案及已下载文件。
- 使用单独的安装配置路径，不能复用检查配置；真实执行需保留系统的自动/手动安装标记，
  不能误把检查缓存中的 `extended_states` 当成正式安装状态。
- 日志目标在私有任务目录中，`UMask=0077`。提交器必须先创建并校验 root-only 目录、
  日志文件、隔离 HOME、已审核配置和授权记录。模板存在或 `armed.json` 存在都不足以证明授权。
- 普通停止请求受限，但断电、关机、root 强制终止或系统故障仍可能中断安装。
  不承诺所有断线场景均可自动恢复，也不使用 `KillMode=none` 放任失控进程。

启动器是私有的独立 Python 文件，只使用系统标准库并通过隔离模式运行；
验证本次授权后先独占写入执行标记，再以固定环境替换自身为 APT，不另行派生前台安装子进程。
这些内部实现仍不能直接用于生产升级。

## 下载及安装前校验

`packagedownload.PackageDownloads.stage()` 是内部缓存准备接口，由独立材料命令复用；
不能单独调用，没有安装、菜单或自动接续能力。
需要显式下载确认和受限的非空任务；复用受管部署检查与协作锁，不暂停服务或续期。
不接受用户提供的下载 URL、旧报告中的摘要或任意包清单作为可信来源。

- 独占创建与任务编号对应的缓存，用固定官方源和独立配置重新刷新索引。
  APT 负责签名、TLS、有效期和包下载认证，依赖本机 Debian 密钥环；本工具不声称验证了包的独立签名。
- 从新索引查询候选和来源，再按精确任务版本模拟完整动作并应用修订更新限制。
  候选、依赖、版本、hold 或架构与计划不符即停止；无更新不能借此执行同版重装。
- 读取目标包的结构化元数据，要求包名、完整版本、架构、大小和 SHA-256。
  使用标准字段解析器，拒绝重复字段、多个记录、异常路径、缺失摘要或超出范围的大小。
- 只执行 `--download-only`；不解包到系统、不执行维护脚本、不安装或移除软件。
  下载失败、中断或状态不明时保留缓存，不重试、不进入维护、不调用系统服务控制命令。
- 对实际缓存文件分块计算摘要，拒绝符号链接、硬链接、异常权限、额外包、缺包及读取中替换。
  不假设缓存名等于仓库文件名；按大小和摘要匹配唯一目标，再用只读 `dpkg-deb --field`
  核对包内名称、版本和架构。不会执行包内程序。
- 下载后再次模拟动作，并复核安装状态、受管配置、服务观察、签名索引文件及系统自动安装标记未变。
  完成后返回内存中的绑定对象，可重新核对缓存文件、索引和配置；它不是持久化升级授权或执行完成记录。
- 下载配置只写独立缓存的 `extended_states`；后续安装配置指向系统实际的
  `/var/lib/apt/extended_states`，避免误用空的检查状态。真正安装时保留自动/手动标记仍须
  单独验证，不能仅凭这个路径正确就宣称已保证不变。

当前限制单个包 64 MiB、所有预期包合计 256 MiB；索引文件有独立读取上限。
这些是识别与检查限制，不是磁盘配额。没有下载文件自动清理、断线后重用或失效缓存恢复入口。
下载阶段缓存只保存公开索引、软件包和固定配置，不复制 Token、节点密钥或证书。
材料命令另行保存的本机控制资料可能敏感，须遵循[材料隐私要求](package-review.md#材料和隐私)。
不读取 `partial` 目录中的未完成内容，也不修改 `_apt` 的目录归属。
任何后续后台提交仍须重新核对主机状态、完整依赖方案、索引新鲜度和文件绑定。

以上仅在本地模拟主机和无害子进程测试中验证；尚未进行 Debian 实机下载及实际更新验收。

## 一次性提交

`packagesubmit.submit()` 仅接受仍在持锁上下文中的 `GuardLease`、对应的下载绑定对象，
以及明确的升级确认和单独审查确认。审查确认只是调用者对模块/维护脚本审查的断言，
不是自动审查结果；分阶段内部接口要求独立审查本轮材料，目前没有公开用户升级入口。

- 提交前再次核对维护保护、包数据库、保留配置、缓存文件、索引、安装配置及包审计。
  用实际安装配置模拟完整动作，必须与已审核的精确包版本和范围一致，不能复用旧模拟结果。
- 独占写入本次提交意图、私有 HOME/日志/启动器及静态服务文件；拒绝已有同名任务或其他覆盖。
  检查服务语法、加载后的模板和未启动状态，然后再次核对文件身份、内容和当前主机状态。
- 在调用 systemd 前持久化提交尝试、授权和内容绑定记录。即使写完记录后尚未提交就断线，
  也不得把“看起来没有启动”当成重试授权；部分记录需要单独核查。
- 新提交额外保存私有的安装前基线摘要，并在第二版提交绑定记录中关联它的身份和内容摘要。
  基线不复制 Token、密钥、域名、证书内容或完整软件包数据库；仅保留完整基线的摘要、
  开机标识、批准的版本变化、自动安装状态摘要以及必要的发行版文件和保护记录摘要。
- 只调用一次 `systemctl start --no-block`。成功返回只表示提交被接受，不表示安装已开始或已完成。
  超时、中断、非零返回或结果记录失败都不自动补交，也不停止后台任务或解除保护。
- 后台启动器核对私有目录、授权内容和 systemd 执行身份，再用排他创建写入执行标记并同步落盘。
  同一任务的另一执行器无法取得标记；标记即使为空、损坏，或创建后尚未运行 APT 就发生故障，
  仍不能自动重跑。启动器使用 `execve` 保持主进程身份，并只传递固定的必要环境变量。
- 提交器退出后保留维护保护和待核查状态，不修改安装版本归属记录，不恢复服务，不声称升级完成。
  协作锁不能阻止其他 root 操作；记录和原子创建也不保证断电后的包数据库完整性。

没有开机自动接续、失败重试或恢复后再提交入口。当前测试中的后台执行效果被替换为无害文件写入，
不运行真实 APT、不安装软件。一次性标记已做并发和故障注入测试，但尚未进行真实 systemd 升级验收。

## 只读任务观察

`JobObserver` 没有默认真实执行器，必须显式注入文件访问和查询函数。
它只读取匹配模板的本机服务文件，以及固定字段的 `systemctl show --all`，不读取原始包日志。
查询前后复核文件内容及身份；要求固定服务路径、无额外覆盖、无自动重启、无待重载配置。

观察会分别报告：尚未启动、运行或排队、命令成功退出、命令失败退出、无法判断。
仅有 `ExecMainStatus=0`、`inactive` 或停止状态不能作为成功依据。
捕获到执行身份和开始时间后，不再接受另一轮执行、重置或消失的结果。
内部 `packagesubmit.observe_submission()` 在重新连接后持锁核对提交记录、启动器和服务文件，
并要求执行标记中的 systemd 身份与当前观察一致；查询前后复查记录未变。
没有执行标记、记录不全或身份改变时只报告待核查，不补交、不删除标记、不推定升级完成。
它不读取原始包日志，也不使用升级前的包数据库未变断言误判已升级后的状态；尚无公开查询入口。

等待预算只约束观察者，不给后台安装任务发送停止或重试指令。
查询失败、超时或用户中断不能推导为安装任务失败或已停止；状态不明时仍需核查。
即使命令成功退出，报告也始终 `upgrade_completed=false`、`postchecks_required=true`，
因为软件包状态、配置、服务、TLS、续期和客户端尚未验收。

## 维护启动保护

`packageguards.PackageGuards.protected()` 供内部协调器在完成新一轮包审核、下载验证和
停机确认后调用，没有 CLI 或默认真实执行器。测试只使用临时目录和模拟主机。
不接受空任务；没有更新时应在协调器上层直接结束，不能进入维护。

- 操作前核对受管部署、当前证书、本机 TLS、包状态、SSH/UFW 和相关服务；
  版本、hold、额外覆盖、已有策略或 mask 不符时停止，不覆盖或认领已有文件。
- 持有既有协作锁直到调用者退出；先写入私有更新意图，再创建分阶段记录和启动策略。
  意图只包含任务编号、包版本和停机确认，不复制 Token、节点密钥、域名或证书。
- 暂停并禁用 Certbot 定时器，复用已测试的最多 90 秒、连续两次空闲观察。
  正在执行或排队的续期须自然结束，不强制停止 Certbot；超时保留记录和当前保护。
- 复核保留资源后，独占创建 Nginx/Certbot 的持久 mask，重载服务定义。
  如果续期在观察后又进入运行，不强制终止，也不继续停止 Nginx。
- 停止 Nginx，再核对三个目标均已受保护且不在运行、本机 TLS 端口无监听、
  节点配置/凭据/证书/包数据库未改变、Snell/ShadowTLS 仍运行、SSH/UFW 不变。
  这段维护会使新的节点握手不可用，不能宣称无停机更新。
- 保护检查仅适用于安装前；真正安装后包数据库和发行版文件可能合法改变，必须使用
  后续升级后验收逻辑，不能放宽这里的比较来伪造通过。

上下文退出、异常或中断都不自动解除 mask、恢复续期、重试或删除更新意图。
即使保护准备成功，也没有安装包、创建/启动后台任务、改写安装版本记录或完成升级。
尚未完成实际包审查、用户入口和实机验收，不应在真实 VPS 单独调用此接口。

`install-status` 能提示未完成更新；正常管理以及旧的 Token/清理恢复入口会拒绝继续变更。
这不是全系统互斥锁，旧版工具、其他 root 操作或直接执行的 Certbot 不受它控制。
状态记录不证明后台任务已退出，也不能作为手动删除标记或重启的依据。

## 安装后验收及恢复

`packagefinish.PackageFinish` 必须保有原始有效的 `GuardLease` 和同一任务的下载绑定对象，
或由下面的受限接续流程重新核对后生成只允许恢复的上下文；两者都必须持有协作锁。
必须分别确认恢复服务、DNS 演练及恢复正式续期。没有 CLI 或默认真实执行器。
它不把失效租约重新启用，也不是通用断线/重启恢复命令。

1. 核对提交记录、执行标记与实际 systemd 执行身份，要求后台任务明确成功退出且身份未变。
   运行中、排队、无执行标记、退出结果不明或另一次执行都不能进入恢复；不重新提交安装任务。
2. 比较完整已安装包集合、架构、版本和 hold，要求仅发生批准的精确版本变化，并要求 `dpkg --audit`
   没有异常。额外依赖、新增/删除包、半配置状态、其他版本变化都停止；不执行自动修复。
   自动安装状态文件允许身份或时间改变，但内容摘要必须保持不变；内容重排等差异也保守停止，
   不自动执行 `apt-mark`，不把“当前文件能读”当成标记已保留。
3. 节点配置/程序、凭据、续期集成、Nginx 基础配置、SSH/UFW 和记录继续要求与维护前一致。
   软件包自带服务文件只允许在其所属包获准更新时变化，并与当前本机包清单摘要核对；
   随后绑定新文件，拒绝验收中再次变化。这是本地一致性检查，不是上游签名或独立来源证明。
4. 先只移除本任务拥有的 Nginx mask，重新加载并检查服务，启动 Nginx，验证监听及两个入口的本机 TLS。
   Certbot 的保护此时仍保留。任何启动结果不明或 TLS 失败都会停止，不自动再启动或回退包版本。
5. 解除本任务拥有的 Certbot mask 后，要求定时器仍停用、服务空闲、实际加载配置正确且不待重载。
   执行一次指定证书的 DNS 演练和部署钩子，要求新的 DNS 挑战、传播等待、重载及模拟续期证据；
   零退出码本身不够。演练不得改变正式证书、凭据或保留配置。
6. 演练和复核均通过后，按原文件身份及摘要原子更新 `packages-ready` 的直接组件版本记录。
   再次检查后恢复定时器。此后可能发生真实到期续签，不再要求正式证书代次不变，
   但新证书仍须通过已有证书、TLS 和续期配置检查。
7. 最后移除本任务的启动策略，重新验收，保存私有完成证据，再清除活动更新意图。
   历史任务、日志和分阶段记录保留；仍需外部客户端和重启验收，报告不会宣称完整升级验收结束。

每步先记尝试，再执行；异常、中断或部分写入均保留尚存的保护、记录和当前状态。
不会强制停止 Certbot、自动重装、回退包版本、再次提交或删除失败意图。
发生失败时 Nginx 可能已经恢复、版本记录可能已经更新、定时器也可能已经启用，不能一概宣称仍停用。
若最后报告写入失败但完成证据和意图清理已验证，只如实报告缺少最后报告，不伪造事务回滚。

本接口仅在模拟主机上测试。实际 Debian 包升级、原有模块及维护脚本审查、真实断线/断电和
服务恢复仍未实机验收。不应在真实机单独调用维护、提交或恢复接口。

## 内部协调及受限接续

`packageflow.PackageFlow.run()` 串联新下载、独立审查、保护、单次提交、有限观察和安装后恢复。
它仍只接受经过范围筛选的非空任务，不能从历史 JSON 导入任意安装命令。
调用者须明确确认联网、停机、安装、恢复服务、DNS 演练和正式续期。
模块/维护脚本审查是单独的必需回调，收到本轮实际校验的包后必须明确返回通过；
没有默认批准或自动审查。拒绝审查时只保留下载缓存，不进入维护。

提交结果不明或观察等待结束时，不再安装、重启或取消后台任务，也不自动进入恢复。
保存的基线与提交绑定使之后的专门核查有据可查，不代表所有中断都能接续。

`PackageFlow.resume()` 只接受以下交集，并仍需独立确认恢复及 DNS/续期副作用：

- 第二版提交绑定及其私有基线完整、权限正确、身份和摘要未变；旧版提交仅能观察，不能补造基线。
- 系统仍在同一次开机，后台任务的执行标记与当前 systemd 执行身份一致，且明确成功退出。
  运行中、失败、丢失标记、未知结果、重启或任务重新执行均停止，不重交安装任务。
- 没有其他待核查操作，也没有任何安装后恢复尝试或接续尝试记录；恢复过一半的现场不在支持范围。
- 从现用受管资源重新读取原有配置、凭据和证书的校验依据；仅在内存中将本次获准包的
  精确新版本映射回其原版本。完整重建基线摘要必须等于安装前摘要，不能以当前状态另建基线。
  这不安装旧版本，也不保存秘密副本；其他包、hold、配置或证书变化仍会阻断。
- 原保护完整且身份相符，包审计、安装标记和发行版文件检查通过；保持原协作锁。

通过后先独占写入接续尝试，再复用同一套安装后恢复步骤。恢复上下文不被安装提交器接受。
接续标记一旦写入，即使随后尚未恢复服务就中断，也不能再接续；保留现场等待人工核查。
基线、尝试、绑定和报告均只留在私有任务目录，诊断结果不输出开机标识、基线摘要或秘密。
不扫描全部历史任务自动挑选，不读原始安装日志，不自动下载、安装、修复、回退或删除记录。

以上为模拟主机测试通过的内部接口，不能据此在 VPS 手动构造调用；尚无用户可执行接续命令。

## 包内容与分阶段确认

`packagereview.collect()` 在已有协作锁内检查本轮下载对象，返回仅保留在内存的审查材料。
材料不是安全结论、可导入的升级计划或持久授权，不能仅凭摘要相同或输入一次 `y` 当作已审核。

- 使用固定只读 `dpkg-deb --ctrl-tarfile` / `--fsys-tarfile`，再由标准 tar 解析器读取成员。
  不将包展开到文件系统、不执行脚本、不打开包内链接目标；解码前后核对实际包文件绑定。
- 解码输出写匿名临时文件，有总量和等待上限；超限、失败、中断或包变化均不返回部分通过。
  这个子进程可以终止，因为它只读取包；不改变后台 APT 安装不可随意终止的边界。
- 控制区最多 4 MiB、数据区最多 128 MiB；控制成员最多 64、数据成员最多 10000。
  脚本文本有独立上限，重复/越界路径、设备、稀疏文件、PAX 扩展、未知控制文件及非 UTF-8
  脚本保守停止，不截断后声称完整。该有限解析范围尚待目标 Debian 包样本验证。
- 再核对包内名称、架构和精确版本。收集候选维护脚本、触发器、配置文件声明及完整成员清单，
  为常规文件计算摘要，列出权限/属主和链接文本。控制区 `md5sums` 只保留摘要，不用它替代来源认证。
- 通过 `dpkg-query --control-list` / `--control-show` 读取本机已安装版本的控制资料，
  对比旧/新维护脚本、触发器和配置声明是否新增、删除或改变。旧脚本也可能在升级中被调用，
  因而不能只审核候选包。未知资料、无效编码或查询失败都会停止。
- 首版只允许没有额外 Nginx 动态模块的既有基线。已安装模块包、启用目录非空或候选包含模块时停止；
  不自动卸载模块，也不声称相近版本已经兼容。完整 Nginx 配置仍须通过已有维护检查。
- 完整材料用 ASCII JSON 转义终端控制字符；它包含本机控制脚本，可能涉及本地改动，
  只能用于本机审查，不应直接发送给 AI 或发布。可分享摘要不含脚本文本和包内任意路径。
  不读取节点凭据、证书或原始日志，不持久保存新的审查材料。
- 批准之后、进入维护之前及维护保护完成后再次检查下载包、索引、安装状态、现有控制文件和模块目录。
  改变即停止，不能沿用此前批准；协作锁仍不能阻止不遵守它的其他 root 操作。

`PackageFlow.run_staged()` 复用同一个提交和恢复流程，但要求两个不同的显式回调：
一个对完整材料作独立审查，另一个处理固定阶段的操作确认。没有默认审查通过函数。
`PackagePrompts` 复用中文终端的 `[y/n]`，默认拒绝，只接受 `y/Y`；非交互终端拒绝。
这些都是待接入的内部接口，不是已经安装的管理命令。

1. 下载前确认联网和缓存写入。拒绝时不下载。
2. 材料审查通过后，分别确认备用 SSH/控制台及停机、精确版本安装；两项都确认后才进入维护。
   任何一项取消，只保留下载缓存，不停止 Nginx 或续期。
3. 后台安装明确成功后，分别确认服务恢复、DNS 演练及正式续期；三项全通过才执行恢复。
   取消或断线不回滚已经安装的软件，不半途解除保护，也不重新提交任务。
   此时需要及时人工核查；只有满足已有受限接续全部条件时才可继续恢复。

完整材料的收集和差异比较不分析脚本语义，不覆盖未变包的触发器、全部外部引用或任意 root 脚本副作用。
人工审查和后续 Debian 实测仍是必要步骤。旧的 `run()` 保留为内部低层接口，不对用户开放。

## 接入执行前仍需完成

1. 已提供独立的[材料收集命令及失败核查说明](package-review.md)，只下载和按确认保存，不安装。
   完整材料仍须人工审核，收集完成不等于独立审查通过；实际安装不能导入或复用该完成记录授权。
2. 新连接确认及独立升级授权；核对 APT/dpkg 锁、配置冲突处理、包自动安装标记和维护脚本影响。
3. 将已完成的分阶段确认接口接入受限 CLI，并在目标 Debian 验证包解析、维护保护和实际包行为。
4. 实测 SSH 断线后的独立服务观察及符合条件的接续；状态不明不再次提交。
5. 实测安装后验收、记录迁移、服务恢复以及外部客户端、重启后的可用性。
6. 补充当前受限接续之外的失败、中断和部分恢复状态的人工检查说明；
   不自动执行 `dpkg --configure -a`、重装或回退。

本轮本地测试包括无害子进程在观察预算耗尽后仍运行，但不是 Debian/systemd 实际安装验收。
新增依赖、真实软件包升级、断线、断电、重启及客户端验证尚待后续独立测试。

[systemd.service](https://manpages.debian.org/trixie/systemd/systemd.service.5.en.html)
说明 oneshot、退出后保留状态和启动超时行为；

说明环境、执行身份及标准输出配置；
[apt-get](https://manpages.debian.org/trixie/apt/apt-get.8.en.html)
说明固定版本、只下载、禁止下载和仅升级等选项；
[apt-cache](https://manpages.debian.org/trixie/apt/apt-cache.8.en.html)
说明版本查询和包记录输出；
[dpkg-deb](https://manpages.debian.org/trixie/dpkg/dpkg-deb.1.en.html)
说明读取包内字段及控制/数据 tar 输出；
[dpkg-query](https://manpages.debian.org/trixie/dpkg/dpkg-query.1.en.html)
说明通过控制文件列表和内容接口读取已安装包资料；
[Debian 维护脚本规范](https://www.debian.org/doc/debian-policy/ch-maintainerscripts.html)
说明安装、升级和错误处理过程中可能调用的维护脚本。官方文档不能替代实际包审核。

[systemctl](https://manpages.debian.org/trixie/systemd/systemctl.1.en.html)
说明 mask 和停止服务是不同动作，以及 `--no-block` 不等待任务执行完毕；
[invoke-rc.d](https://manpages.debian.org/trixie/init-system-helpers/invoke-rc.d.8.en.html)
说明启动策略的作用范围。策略和 mask 不能阻止任意 root 脚本直接运行程序，
仍须审核将要安装的软件包及维护脚本，不能把保护存在当作所有副作用已被隔离。

[Debian nginx-common 文件清单](https://packages.debian.org/trixie/all/nginx-common/filelist)
列出其 Nginx 服务文件和配置范围；
[dpkg](https://manpages.debian.org/trixie/dpkg/dpkg.1.en.html)
说明已安装、半配置、触发器等待及 hold 等状态；
[apt-mark](https://manpages.debian.org/trixie/apt/apt-mark.8.en.html)
说明自动/手动安装标记的作用及 `extended_states` 存储。

[Linux kernel random sysctl](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/kernel.html#random)
说明 `boot_id` 首次读取后保持不变；这里用于限制接续在同一次开机内。
systemd 的执行身份用于区分服务的不同运行周期，两项联合检查仍不能替代文件和当前主机状态核对。
