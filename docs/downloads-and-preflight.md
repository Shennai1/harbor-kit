# 官方文件暂存与新机预检查

本文中的下载和预检查命令是安装器的准备部分，不会打开真实系统安装开关，
不会更改 UFW、启动服务、申请证书或读取 Cloudflare Token。
另有显式开启、会修改系统的[实验安装向导](install-wizard.md)，尚未完成实机验收。

## 固定版本与校验依据

此轮只接入已手工验证的 Linux amd64 文件：

| 组件 | 固定版本 | 来源 |
| --- | --- | --- |
| Snell | 5.0.1 | `dl.nssurge.com` |
| ShadowTLS | 0.2.25，协议 v3 | `ihciah/shadow-tls` 的 GitHub Release |

版本与指纹保存在代码中的固定清单，不使用 `latest`，不读取远端脚本，
不自动切换协议大版本。官方发行说明出现新版本也不会改变这一行为。
Debian 软件包的安全更新不应套用这里的固定二进制版本策略。

```bash
python3 -m snellctl artifacts list
```

清单中的 SHA-256 来自此前手工测试所下载文件的指纹，**不是独立认证的上游签名**。
HTTPS 证书验证和固定指纹能够检查来源连接与文件一致性，不能证明最初基线没有被篡改，
也不能保护已经被攻陷的本地管理工具。更换指纹必须重新审查、测试并更新代码，不自动接受下载结果。

2026-10-22 在开发机器重新访问两个官方地址，成功下载并通过指纹、压缩包及 ELF 检查。
没有执行下载的 Linux 程序；下载后的临时测试目录已清理。
该次实测中，本机 Python 的默认 CA 路径缺失，测试进程显式使用了系统 CA 文件，未关闭 TLS 验证。
Debian 上应使用受信源的 `ca-certificates`，不能通过忽略证书错误绕过问题。

## 下载到独立目录

以下是本地开发用法，不是让现有 VPS 重新安装。`runtime` 父目录须先存在；
`pwd -P` 获取不含符号链接的物理路径。

```bash
mkdir -p runtime
python3 -m snellctl artifacts fetch --output "$(pwd -P)/runtime/download-check-1"
```

- 仅允许新的绝对路径；父目录已存在且各级路径不能是符号链接。不覆盖或复用已有目录。
- 只访问清单中的 HTTPS 地址；重定向限定在对应官方站点及 GitHub 文件分发域名。
- 使用受信 CA 验证；不读取环境代理配置或浏览器登录信息，不访问私人 GitHub 仓库。
- 校验文件大小和 SHA-256 后才解析压缩包；只允许预期的单一普通文件，拒绝额外条目、路径穿越及符号链接。
- 检查 ELF 类型、64 位小端头部和 amd64 架构；不执行 `--version` 或任何下载程序。
- 暂存目录权限 `0700`，文件 `0600`，没有执行权限。压缩包和程序均保留供后续安装阶段核验。
- 全部通过后才写 `receipt.json`。这是暂存完成记录，不是可执行授权；未来安装前仍需重新核验文件。
- 网络失败、指纹变化、磁盘错误或中断时停止，不自动重试、不切换镜像、不清理未知文件。
  已写入的部分文件可能留下；重试须另选新目录。不完整目录不得作为安装输入。

单次网络阻塞设置 20 秒超时，读取过程中检查 180 秒总时限，并限制最大字节数。
这不是对操作系统 DNS 解析耗时的绝对保证；连接迟迟不结束时可取消。
不支持断点续传，也没有正式下载缓存或自动清理机制。
目录保护依赖本地 POSIX 文件系统；不防御同一用户或 root 主动篡改暂存目录。

## 新机只读预检查

```bash
python3 -m snellctl preflight --domain node.example.net
python3 -m snellctl preflight --domain node.example.net --public-port 24443 --snell-port 32001 --tls-port 32443 --json
```

此命令应在有项目代码的目标机执行，首轮仅接受 Debian 13 / amd64，完整检查需要 root。
开发机器可以调用，但会报告平台不匹配，不运行 Linux 管理命令。
不必在已经部署成功的测试 VPS 上执行；现有节点会按“非空白新机”被拒绝。

检查范围：

- 当前系统、软件包、IPv4/IPv6 监听和 UFW 状态；沿用脱敏诊断，不读取进程完整参数。
- 拟用端口是否冲突，是否能识别 SSH 监听；不假定所有机器使用同一个 SSH 端口。
- 已有节点、Nginx、证书组件、防火墙持久化组件及拟用配置路径。发现即停止，不自动接管或删除。
- 软件包是否存在未完成的配置操作，本地 APT 索引能否提供全部所需候选包。
- 在 `--simulate --no-remove` 下模拟依赖安装，失败或涉及卸载时停止。

APT 模拟结果只用于本次有限检查，不会执行真正的安装；不把原始仓库 URL、软件包错误文本输出到报告。
退出码 `0` 表示上述有限检查通过，`1` 表示发现阻断项，参数错误为 `2`。
即使返回 `0`，报告中的 `install_ready` 仍为 `false`。

**独立预检查命令尚不覆盖的条件：**

- 成功刷新全部软件源，例如目标机实际安装阶段的 `apt-get update --error-on=any`，
  然后重新核对版本、来源信任、安全补丁及依赖；目前不判断缓存是否最新，也未认证候选包的源。
- Nginx 包安装期间阻止默认公网站点启动，并保护原有服务 mask、配置与软件包状态。
- SSH 新连接验证、完整防火墙与云安全组核查；当前不保证某条端口规则不被自定义规则抢先拦截。
- DNS、CF 凭据、证书、实际 Nginx 版本与配置检查、服务启动和端到端验收。

实验向导已串联组件准备、签发和激活，但并未覆盖全部自定义规则及外部可达性审计。
APT、DNS、ACME 与服务状态不能依靠现有沙盒文件事务整体撤销。
