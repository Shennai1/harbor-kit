# 续期暂停、等待和恢复验证

实验入口，尚未完成 Debian 实机验收。只验证一次暂停和恢复流程，不继续旧域名清理。
不安装快捷命令、不增加菜单入口、不直接执行 Certbot，也不改节点、SSH/UFW、DNS 或云端令牌。

## 适用范围

仅限完整受管的 Debian 13 / amd64 / IPv4 TCP 单节点 main，且同时满足：

- 存在旧域名清理活动标记，原报告证实在删除前的暂停阶段停止，两项删除尝试均为 false。
- 已有成功的受限续期恢复记录；当前定时器实际启用、任务空闲、现用配置与本机 TLS 健康。
- 原意图、失败与恢复记录未变，旧证书及独立凭据仍在，没有其他待处理变更。
- 本清理现场从未执行本验证；存在验证目录便拒绝再次运行，不覆盖结果或自动重试。

确认前和确认后都重新核查。仅限这个已识别现场，不是通用续期恢复器。
现有清理标记继续阻止其他管理变更；本验证成功也不解除标记、不授权删除。

经确认交付并校验源码后，入口为：

```bash
python3 -E -s -B -m snellctl probe-renewal-pause --experimental
```

必须有交互终端；使用默认 n 的 `[y/n]` 确认，仅 y/Y 继续。不接受自动确认、域名、路径或秘密参数。
执行前确认备用 SSH 和恢复控制台可用，保持连接，不并行运行管理变更或 Certbot。

## 操作边界

1. 保存新的 0700 私有验证目录和 0600 尝试记录，保留全部原始清理历史。
2. 只执行一次 `systemctl disable --now certbot.timer`，不停止 `certbot.service`。
3. 调用与清理流程相同的有界等待实现：90 秒预算，每次查询最多 5 秒；
   只等待已识别的排队、启动、运行或停止状态自然结束。每轮要求定时器仍已停用，
   服务至少相隔 1 秒的两次观察均为空闲才通过。失败/未知/缺失字段立即停止验证。
4. 等待通过后仍严格检查现用配置、证书、本机 TLS 和旧资源，绝不跳转到删除操作。
5. 无论验证通过、超时或捕获到异常，都重新核对当前续期目标、软件包服务配置、管理记录及凭据，
   然后最多尝试一次 `systemctl enable --now certbot.timer`。恢复不要求强停仍在运行的任务。
6. 检查恢复状态、节点本机健康、旧资源和清理标记，保存脱敏报告。不得把部分通过报成完整通过。

执行器另设命令白名单：除指定定时器的各一次停用/启用外，只允许现有健康核查使用的只读命令。
所有直接 Certbot 命令、服务 stop/start/restart/reload、软件包操作和防火墙变更均被拒绝。
代码不删除证书、凭据、意图或历史文件；常规本机 TLS 请求及系统命令仍可能产生服务日志。

停止定时器不保证已排队/运行的服务同步停止。恢复定时器可能触发当前证书的真实到期续签，
因此这不是“全系统绝无网络或证书变化”的承诺。
参考 [systemctl 257 的 disable/--now 语义](https://www.freedesktop.org/software/systemd/man/257/systemctl.html)。

## 失败和断线

恢复前若续期目标、凭据或受管历史被修改，则拒绝自动启用，保留现场并报告；不猜测正确配置。
等待期间实际续签导致证书快照改变时，验证不通过，但仍可在续期目标未变的前提下尝试恢复定时器。
恢复命令失败或结果不确定时，不重试、不反向关闭可能已恢复的定时器。

90 秒仅是等待空闲阶段的预算，不是整项操作时限；前后 TLS/配置核查及启停命令另有超时。
超时只终止状态查询子进程，不杀 Certbot 任务。两个空闲采样也不构成全系统排他锁。

执行阶段不依赖持续终端输出，并暂时忽略普通 SSH 断线的 SIGHUP；退出时恢复原处理方式。
这不能防御强制终止、断电、系统重启或外部会话清理，也不是后台守护恢复机制。
捕获到普通异常或 Ctrl+C 后尝试恢复；再次强制中断可能阻止恢复，不能宣称断线必定安全。
参考 [Python 信号处理说明](https://docs.python.org/3/library/signal.html)。
输出终端丢失时不重复启停或覆盖已保存结果。应重新连接后只读核查，不重跑操作。

## 结果与记录

`pause-probe-passed-cleanup-still-pending` 只表示本轮暂停、等待、严格后检和恢复通过。
还应看到 `renewal_restored_verified=true`、`cleanup_marker_unchanged_verified=true`、
`old_resources_unchanged_verified=true`、`current_service_health=local-checks-passed`。
`cleanup_completed=false`、`cleanup_still_pending=true` 是预期：旧资源尚未清理。

`probe-stopped-renewal-restored` 表示验证未全通过，但已核对定时器恢复；仍需查失败阶段。
`stopped` 不保证续期正常。`renewal_restored_verified=false` 表示未确认，不能当作定时器一定停用或启用。
标记被外部修改或无法读取时 `cleanup_still_pending=not-confirmed`，不会宣称原标记已保留。
本机检查不能代替用户从客户端测试公网节点，也不代表真实到期续签已验收。

记录在 `/var/lib/snellctl/preparation/renewal-pause-probe-*` 新目录，包含 `started.json` 和 `report.json`。
目录名仅关联原标记的内部摘要，不包含域名/Token。旧清理目录的内容和结构不变，
成功后仍可按原受限取消流程核查，但本验证不自动调用它。
报告仅含阶段、固定状态、计数、耗时及脱敏比较结果；不收集原始 Certbot 日志、不显示秘密或域名。
`report_saved=false` 时保留终端 JSON 并核查，不为了补报告重跑。

本地测试采用临时文件系统及服务模拟器。覆盖排队后恢复空闲、等待超时、命令失败/不确定、
配置或凭据改变、证书轮换、旧资源变化、异常、重复运行、锁冲突和记录写入失败。
这些测试不是 Linux/systemd 实机验证，也不证明原故障的具体触发源已确定。
