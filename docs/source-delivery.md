# 开发源码交付

唯一项目仓库：[Shennai1/harbor-kit](https://github.com/Shennai1/harbor-kit)。
当前是开发源码，不是已验收的正式发行版或一键部署脚本。
不会因为打开仓库、下载源码或运行只读命令就安装节点。

## 获取与固定版本

公开仓库支持匿名获取，无须在 VPS 存放 GitHub Token。
有 Git 的机器可克隆仓库；没有 Git 时可下载指定提交的源码压缩包。
实际测试使用已经核对的完整提交标识，不能把会变化的 `main` 当作固定版本。
不使用 `curl | bash` 或把下载脚本直接交给 root 执行。

首次交付的完整提交标识及压缩包 SHA-256 在交付时另行提供，
避免在同一次提交里嵌入它自身的提交标识。下载、校验、解压、运行分开。
提交标识和同一渠道提供的 SHA-256 是固定内容/传输核对，不是独立作者签名。
本项目尚未建立签名发行流程，不能因此宣称供应链验证已完备。

在取得的源码目录，可先执行：

```bash
python3 -m snellctl --version
python3 -m snellctl doctor --json
python3 -m snellctl cleanup-plan --json
```

需要 Python 3.11+。只读清理盘点要求在 Debian 目标机的 root 会话执行，
它不认领旧安装、不卸载、不关闭服务、不修改防火墙。
`doctor` 发现现有节点属于正常提示，不能为消除提示而直接删除资源。

如果需要测试实验安装，必须先完成 [新机实测清单](new-host-acceptance.md) 的开始条件，
并取得针对目标机器的单独授权。本阶段不要在正常使用的旧节点执行 `install --experimental`。

## 公开文件检查

在本地源码目录运行：

```bash
python3 tools/public_source.py
```

默认只打印固定公开文件清单、大小和内容指纹，不创建归档、不上传文件、不读取私人笔记。
内部交付用的 `--tree` 会输出公开源码内容，不应拿它当作普通运行诊断。
导出器不发现或自动纳入新增文件；清单之外的内容即使存在也不会被复制。
符号链接、非普通文件、超出大小限制、非 UTF-8 或基础凭据模式命中时停止。
测试中的密码/地址是构造的测试数据，不是任何服务器的运行凭据。

`.gitignore` 另外排除私人工作笔记、运行目录、凭据和构建产物，但忽略规则不是保密保证。
首次及后续提交仍需人工核对；不要使用无差别整目录上传。
公开历史可能被复制，删除文件不等于清除历史副本。

不通过仓库 Issues 上传原始凭据、客户端配置、证书私钥、完整日志或 shell 历史。
诊断只提交脱敏阶段和检查结果。
