# 受控重装（实验版）

仅接受本工具已经完整卸载的 Debian 13 / amd64 单节点 main。
这是独立的交互式执行入口，不是新机安装，也不是中断恢复；尚未完成 VPS 实机验收。
固定版本源码交付需单独确认，不应从未核验的分支直接以 root 执行。

```bash
python3 -E -s -B -m snellctl reinstall --experimental
```

必须使用真实交互终端。全部确认使用默认 n 的 `[y/n]`；不能提供自动确认或明文 Token 参数。
域名、三个业务端口重新输入，SSH 端口须与已验证的卸载历史和当前监听、规则一致。
域名可以沿用，也可以更换；选择对应区域 DNS 编辑权限的专用 Token，隐藏输入并存入 root-only 文件。
不调用第三方一键脚本，不沿用已删除的节点密钥，不安装常驻快捷命令或网页面板。

## 写入顺序

1. 重新执行卸载后只读检查，核对历史、软件包、停用服务及 SSH/UFW。
   新端口必须空闲；未知历史文件、非空受管目录、外部配置或活动变更标记会阻止操作。
2. 确认资源只用于本项目、独立 SSH/恢复控制台可用、域名管理授权与现行 CA 条款。
   从既有官方固定来源下载程序并验证摘要；再次确认本轮写入。
3. 取得并持续持有原 `preparation/lock`。写入 `reinstall-intent.json` 后，才开始归档或改动目录。
4. 将上一轮已识别的阶段记录和私有诊断目录原位移动到
   `/var/lib/snellctl/preparation/generations/<随机编号>/records/`。
   保留原锁、owner、隔离 HOME 和所有更早的分代目录；不删除历史或 ACME 账户。
5. 只移除已检查且仍为空的节点目录、版本目录及相应空服务覆盖目录，为新部署建立目录结构。
   不递归清空任何目录，不卸载软件包。Nginx 默认站点链接只在软件包启动保护已核对时重建，随后由激活流程移除。
6. 复用既有准备引擎刷新全部 APT 源，使用独立的签名 Debian 索引选择候选版本、模拟依赖并以 `--no-remove` 安装。
   使用临时服务 mask 和启动策略防止 Nginx 默认端口或 Certbot 定时任务提前启动。
7. 输入本轮 Token，执行 DNS 演练，单独确认正式签发。生成新的独立 Snell/ShadowTLS 随机密钥。
   激活时公网入口仍为回环监听，完成本机 TLS、错误 SNI/无 SNI 拒绝及模拟续期重载检查。
8. 再次确认自动续期、独立 SSH 新连接及公网开放，只新增所选 IPv4 TCP 入口规则。
   复查服务和归档元数据，写入重装完成记录，最后移除活动重装标记。

## 历史与中断

`manifest.json` 记录原路径前缀、归档前缀及文件元数据，权限 0600；目录 0700。
归档采用同一文件系统内重命名，保留文件内容和 inode，不另存旧秘密副本。
历史文件内部的绝对路径不改写，只作为历史线索；不能当成当前配置或恢复脚本使用。
历史元数据核查不是对抗恶意 root 的完整性证明，协作锁也不能阻止外部 root/Certbot 并发操作。

任何写入后取消、失败、掉线或断电，都可能留下部分归档、已安装包、候选配置或远端 CA 结果。
`install-status` 的 `reinstall=needs-inspection` 优先表示整个流程尚未确认完成，其他阶段字段可能处于新旧记录交接中。
程序不会自动恢复、回滚、删除标记或重试。保留现场，不运行 `install`、`resume` 或重复 `reinstall`，不直接重启。
成功卸载后的重装属于受限流程；失败现场的接续尚无执行入口。

## 验收边界

`reinstalled-external-test-required` 表示服务端流程和本机检查完成，不代表公网或重启验收通过。
需另行确认显示新客户端配置，测试延迟和实际使用，再验证重启后的节点、自动续期和 SSH。
软件包可能被升级，ACME/Cloudflare 有远端副作用；删除本地文件不能完整撤销。
不支持直接接管第三方、手工节点、多节点、部分卸载、Debian 12、ARM64 或 IPv6 入口。

本地测试使用临时文件系统及模拟系统命令，不连接 VPS、Cloudflare 或 CA，也不执行真实软件包安装。
