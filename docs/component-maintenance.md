# 组件维护只读盘点

首个入口为 `maintenance-plan`，仅支持本工具完整受管的 Debian 13 / amd64 / main。
这不是升级执行器，也不生成可直接执行的升级命令。不要手动替换文件或修改归属记录来绕过检查。

在受管主机的 root 交互终端、已核验源码目录中运行：

```bash
python3 -E -s -B -m snellctl maintenance-plan
```

确认使用 `[y/n]`，默认取消；不接受 `--yes`、目标版本或 Token 参数。
本入口没有接入菜单，也不安装永久快捷指令。尚待单独实机验收。

## 盘点内容

- 复用现有协作锁，拒绝未完成的管理操作及已卸载现场。
- 核对受管节点配置、程序文件、配置模板和本机归属记录；域名、端口均从现有配置读取。
- Snell/ShadowTLS 展示受管基线版本和固定官方下载地址，不重新下载或运行它们。
- 查询 `ca-certificates`、`nginx`、`certbot`、`python3-certbot-dns-cloudflare` 的已安装完整版本，
  与最近安装记录比较；识别 hold 状态，不解除 hold。四项不代表全部依赖已盘点。
- 核对 Nginx 自报版本与部署绑定、基础配置及本地包配置摘要，核对受管续期覆盖文件。
- 核对专用 Debian 软件源文件是否仍符合模板，以及公共密钥环是否能按受限路径读取。
- 只观察两个节点服务、Nginx、Certbot 服务与定时器的加载/启用状态；复查已读文件和版本是否变化。

报告中的 `configured_upstream` 是代码内的固定来源，不来自用户配置或网络响应。
`managed_version` 是受管基线版本，不是正在运行进程的版本证明。
Nginx 的完整 Debian 包版本与 `nginx -v` 的短版本分别展示，不互相代替。

## 结果解释

- `component-inventory-complete-no-changes`：本次有限盘点完成且未发现列出的差异，不表示最新、安全或允许升级。
- `component-inventory-review-required`：盘点完成，但发现包版本变化、hold、包审计输出或服务状态需要核查。
  包版本变化本身不等于入侵，也可能来自其他合法维护；本入口不自动认领或修复。
- `blocked-preserve-all`：配置不符、文件/记录损坏、锁冲突、平台不支持、查询失败或核查期间变化；不执行后续变更。

只有第一种结果返回退出码 0；需要核查或阻断返回 1，取消返回 130，非交互入口返回 2。
任何结果都保持 `update_implemented=false`、`update_authorized=false`、`update_ready=false`。
报告不持久保存，只分享最后的 JSON；不要分享客户端配置或秘密文件。

## 不做的事情

不联网、不刷新 APT、不查询候选版本或漏洞库、不安装或卸载软件、不访问 Cloudflare/CA。
不运行 Certbot、不签发证书、不重载/重启服务、不改 UFW 或 SSH、不清理历史。
读取受管节点配置用于内存校验，但不输出密钥；不读取 CF Token、证书/私钥、ACME 账户或原始日志。
系统查询使用受限环境及匿名临时输出；不保存盘点报告，常规文件读取可能更新访问时间。

本地记录和摘要不能证明程序安全、上游签名、安装包下载来源或当前补丁状态。
专用源及密钥环核对不重新验证缓存索引或包签名；不读取其他系统软件源或输出其中的私有地址。
服务字段观察不包括 TLS、证书有效期、端口、防火墙、公网可用性、进程可执行文件或完整依赖闭包。
核查期间不暂停定时器；续期可能正常开始，因此观察到忙碌会要求核查，不会停止它或自动等待重试。

## 后续更新边界

真正更新仍需要另行实现和验收：上游与补丁审查、可信索引刷新、全部依赖和模块方案、明确版本选择、
组件分别确认、维护记录与模板兼容处理、适用的恢复方案、实际运行及客户端验收。
不会自动切换协议大版本；不能把复制回旧程序文件当作 APT 软件包变更的通用回退方法。

## 参考

包字段及 hold 状态依据 [Debian dpkg-query 文档](https://manpages.debian.org/trixie/dpkg/dpkg-query.1.en.html)。
[Debian apt-cache 文档](https://manpages.debian.org/trixie/apt/apt-cache.8.en.html)说明缓存信息可能过期，
部分查询会生成缓存；本入口不调用 APT，也不据缓存推断最新版本。
