# 实验版新机安装向导

本批把准备、激活、续期和公网启用模块串联为中文 SSH 向导。
**仍属实验功能，不是正式发布版。** 用户已在 Debian 13 / amd64 测试机完成一轮安装：
SSH 断线后经人工核查并用一次性命令接续，节点实际使用与正常重启通过。
无需人工接续的完整向导、下述新菜单接续入口仍待独立实机验证。
现有手工部署并正常使用的 VPS 不应运行此入口。

## 入口与边界

需要 Python 3.11+、Debian 13 / amd64、root、运行中的 systemd，以及交互终端。
限定单节点 `main`、Snell 5.0.1、ShadowTLS 0.2.25 / 协议 v3、IPv4 TCP。
已有 Nginx、Certbot、旧节点或本工具准备记录会停止新机安装，不自动接管。
UFW 必须已启用、开机启用、默认拒绝入站并允许出站，SSH 已放行。
这不是完整 nftables、自定义链、云安全组或公网可达性审计。

默认菜单仍为只读。显式开启实验入口才会显示安装及受限接续选项：

```bash
python3 -m snellctl menu --experimental
```

也可以直接进入同一向导：

```bash
python3 -m snellctl install --experimental
```

没有 `--yes`、Token 参数、凭据环境变量接口或系统根目录替换开关。
参数错误不会回显原始参数；但不能清除用户自己误输入命令时留下的 shell 历史或进程参数。
标准输入、输出、错误输出均需为终端，不能通过管道预填回答或重定向运行记录。
这还不是 GitHub 远程安装命令，也不会安装全局 `snellctl` 启动器。

## 操作顺序

1. 输入完整小写域名、三个可变节点端口及当前 SSH 端口。SSH 不假定为 22，四个端口不能冲突。
2. 只读预检查已有组件、端口、路径、APT 候选和依赖，再提前检查 UFW 规则及 SSH 监听。
3. 展示部署范围，分别确认实验安装风险和现行 Let's Encrypt 条款。
4. 下载固定官方程序并验证基线指纹、文件类型和架构；校验失败不进入系统写入。
5. 建立归属记录并准备 Debian 软件包，保持 Nginx/Certbot 启动保护。
6. 隐藏输入本机专用 Cloudflare Token，保存为 root-only 凭据，随后进行 DNS 演练。
7. 演练通过后单独确认正式签发，再安装配置、全回环启动并验收 TLS。
8. 单独确认模拟续期和 Nginx 重载测试。
9. 确认自动续期、从另一终端新建 SSH 登录成功、开放指定 IPv4 TCP 入口，全部确认后才执行公网启用。
10. 核对公网监听、UFW 增量、续期任务和开机启动；提示仍需客户端与重启验收，不自动重启。

下载指纹来自先前手工验证，不是上游发布的签名。安装时会再次验证下载。
不从环境继承 Cloudflare 令牌；Token 不进入外部进程参数、向导输出或诊断对象。
无法关闭终端回显时停止，不退回明文输入。取消/异常后尽力恢复终端状态。
Python 字符串及运行所需凭据不是加密内存，清空局部变量不代表安全擦除。

当前不提供账户邮箱；正式证书的域名会公开于 CT，隐藏监听端口不会隐藏证书域名。
向导会要求用户阅读并同意 [Let's Encrypt 现行协议](https://letsencrypt.org/repository/)。
DNS-01 使用 Token 创建临时验证 TXT，不负责替用户修改 A/AAAA 业务解析。
外部客户端仍需正确的节点地址、SNI 和配置；完成安装后单独使用 `client` 或菜单 5，明确确认才显示含密钥配置。
详见 [客户端配置说明](client-export.md)。导出不是运行健康检查，也不会修改 Surge。

## 取消与故障

每个确认框默认取消，没有回车默认同意。取消返回 `130`，失败返回 `1`，非交互入口拒绝返回 `2`。
向导完成返回 `0` 只说明服务端流程通过，不表示外部节点、重启或真实证书轮换已验收。

进入系统写入前取消，不写入本工具的系统配置；进入后取消则**不是自动卸载或回滚**。
软件包、启动保护、凭据、证书、服务、规则和 CA 结果可能已经存在。
特别是公网启用后半段失败，可能已经启用了自动续期或留下新增的放行规则。
本工具不因此盲删防火墙规则、解除保护、重签证书或换密钥。

终端只输出固定阶段、固定排查提示及一行 `snellctl-diagnostic` JSON，不直接打印异常、
系统命令输出、Token 或原始日志。不要把 Certbot 日志、凭据文件或进程参数整体贴给 AI。
软件包管理器、Certbot、systemd 仍可能保留各自本机日志；这不是“系统零日志”保证。

可以单独读取不含域名、IP、密码和 Token 的阶段记录：

```bash
python3 -m snellctl install-status
python3 -m snellctl install-status --json
```

该命令不执行系统管理命令，不写入/修复记录，不联网，不自动恢复。
“有完成记录”只表示曾记录完成，不表示当前服务健康；未找到记录也不表示没有别的服务。
记录损坏、权限异常或锁被占用时报告不可读取，不显示原文件内容。
状态返回 `0` 也不意味着安装成功或没有待处理阶段。

发生中断后保留现有 SSH，并用另一终端确认可以登录。先读阶段记录再排查，
不要直接重启、重跑安装、删除状态目录、解除服务 mask 或重置 UFW。
**目前没有通用系统变更恢复、卸载、换域名/Token 或升级入口。**
已完成节点的单项密钥更换是独立实验入口，不属于安装或接续，见[密钥更换](key-rotation.md)。
仅有下述严格限定阶段的接续；不能用于所有失败或未知结果。

## 受限接续

```bash
python3 -m snellctl resume --experimental
```

也可在 `menu --experimental` 中选择 `7. 中断后检查并继续`。
它只接受单节点 main，要求 guards、packages、dns-test、certificate、activation、renewal-test
均有完成记录，且 renewal-enable/public 均未开始；不能接管手工或其他脚本节点。
已正常完成部署的机器无需执行，发现完成记录也会拒绝接续，不重复添加规则。

1. 先确认原安装进程已退出，不在其他会话同时安装、升级或改配置。
2. 程序只读检查阶段记录；阶段不符、损坏、缺失或锁被占用时停止。
3. 输入原部署完整小写域名、原定公网端口、Snell/Nginx 本机端口及当前 SSH 端口。
   四个端口均必填，无默认值，不从历史 VPS 猜测；输入只用于比对，不修改原配置。
4. 在锁内复查记录绑定、文件身份/内容/权限、软件包版本、证书及本机 TLS、
   服务和回环监听、启动保护、UFW/SSH、Certbot 原厂服务及配置。复查不联系 CA。
5. 复查通过后展示范围，重新分别确认“自动续期”“已重连”“开放”；任何其他回答都取消。
   独立 SSH 登录由用户实际完成，程序不能替代这个验证。
6. 执行前再次取得锁并重复现场检查。等待确认期间的配置漂移、其他进程开始或完成公网操作，
   都会阻止此次接续，而不是沿用前一次检查结果。
7. 只进入原有公网启用流程；不下载、安装软件、重做 DNS 演练或初次证书签发，不换密钥。
   正式 Certbot 任务仍可能执行到期续签，之后核对入口、规则增量、timer 和开机启动。

接续不保存第二份配置或新增 Token 副本，不显示密钥，不生成客户端配置文件。
成功仍需客户端与重启验收；它不会自动重启或替用户关闭旧 SSH 连接。
如果机器已经重启导致本机服务停止，或软件包/配置发生变化，会停止而不是自动启动或覆盖。
已有公网/续期意图但无完成记录时也停止，不能借此重复未知结果的操作。

只读复查和交互等待不会预留全系统资源；最终复查也不能防御恶意 root 或其他管理员并发修改。
断线/强制终止后的结果仍须先查 `install-status`，不要删除锁、阶段记录或服务保护。
开始写入后的失败保留原有错误处理边界，不承诺全局回滚、自动修复或断线自动继续。
退出码与安装向导一致：成功 `0`、取消 `130`、拒绝非交互/未显式开启 `2`，检查或执行失败 `1`。

## 测试边界

本批增加向导顺序、独立确认、取消/中断、错误脱敏、菜单门控、状态只读、
真实伪终端隐藏输入及整条流程串联测试。整条流程使用真实控制器和临时文件，
但 APT、systemd、UFW、CA、下载和服务 TLS 在该串联测试中均为模拟。
独立 TLS 测试另有真实本机 socket 验证，不能替代 Debian 组件集成测试。
受限接续新增 35 项本地测试，覆盖真实临时目录中的断点接续、取消/EOF、未知阶段、
已完成节点、锁占用、配置与包版本漂移、服务停止、TLS 失败、确认期间变化和输出脱敏。
其中 APT/systemd/UFW/CA/TLS 由模拟器响应，不记为新接续入口实机通过。

参考：[Python 隐藏输入与回显回退](https://docs.python.org/3/library/getpass.html)、
[Certbot 使用与续期](https://eff-certbot.readthedocs.io/en/stable/using.html)。
