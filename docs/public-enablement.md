# 公网启用、开机启动与自动续期

本批新增内部 `publish.py`，接在本机激活与续期演练之后。
已接入显式开启的[实验安装向导](install-wizard.md)，**不能在现有节点上试装或手动调用内部方法。**
代码具备修改 Debian 主机的能力，本批仅完成本地模拟验证，没有连接 VPS、CF 或 ACME。

## 范围与确认

当前仅支持新机、Debian 13 / amd64、单节点 `main`、IPv4 TCP。
域名、SSH 端口和节点端口来自实际配置，不固定为某台 VPS 的值。
不开放 Snell 后端、Nginx 后端、IPv6 入口或 UDP 入口。

进入此阶段需要：

- 本机激活及同一配置的模拟续期成功，文件和运行状态再次检查通过。
- 明确确认开放 IPv4 TCP 入口，以及启用正式证书续期任务。
- 操作者确认另一个新 SSH 连接正常；程序另外核对指定端口的 sshd 监听及 UFW 规则。
- UFW 已启用并登记开机启动，默认拒绝入站、允许出站；不由安装器重置或代替用户开启防火墙。
- ShadowTLS 入口尚未登记开机启动，已有入口端口或同名规则标签不自动认领。

首次执行正式续期任务可能实际更新已到期需要续签的证书，不只是 dry-run。
不强制重签，不改变 CA，也不绕过之前的条款及正式签发确认。

## 自动续期

保留 Debian 提供的 `certbot.service` 和 `certbot.timer`，不修改软件包文件。
检查服务文件与包内摘要一致且没有额外覆盖后，新建：

`/etc/systemd/system/certbot.service.d/50-snellctl.conf`

覆盖文件明确设置本次域名、运行目录、日志轮转数量和作用范围受限的部署钩子。
Certbot 通过 `env -i` 启动，仅传入指定 PATH、语言和隔离 HOME，避免继承管理员终端配置。
禁用自动遍历目录钩子，只调用本节点已验证的钩子。
服务超时限制为十分钟，禁用 Certbot 自身随机等待，继续使用 Debian timer 的调度。

服务的后置检查额外执行 Nginx 配置测试和重载。即使 Certbot 没有因钩子失败返回非零，
后置步骤失败仍可使 systemd 将本次任务标记为失败；即使不需要续签也会执行这两项检查。

检查后只移除本工具创建的 Certbot mask。先通过实际 systemd 服务执行一次正常续期检查，
再检查退出状态、运行证书和 TLS，最后启用 timer，核对触发服务和后续调度。
临时包启动策略只有在身份及内容仍匹配时才移除，不删除外部修改。

后续 Certbot 可能把本节点 deploy hook 保存为 `renew_hook`；验收只允许空值或这一条精确路径。
非预期钩子、安装器或 `autorenew=False` 会阻断验收。

timer 活跃不是未来每次续期都成功的保证。Token 撤销、DNS/网络失败、CA 策略变化等仍需处理。
当前不提供失败通知或后台监控；真实证书轮换、长时间运行和断电恢复仍需实机验证。

## UFW 增量操作

只执行一条针对选定端口的 IPv4 TCP allow，附带 `snellctl-main` 归属标签。
不执行 reset、disable、reload、default、delete，不修改 SSH 规则，不安装 persistent 系列软件包。
只读调用 iptables/ip6tables 查询指定链，不通过它们写规则。

操作前后核对：

- UFW 原有规则内容和相对顺序保留，只新增一条预期规则。
- 默认配置、before/after 规则及 IPv6 用户规则文件内容未变。
- IPv4/IPv6 INPUT 链与 IPv6 用户链未变，内核 INPUT 默认策略为 DROP。
- IPv4 保存的用户规则与运行链一致，并且运行链只增加预期 TCP ACCEPT。

UFW 的 `show added` 可能把 IPv4 专用规则简写成普通端口规则，因此不根据该显示推断地址族。
另外比较 IPv4 保存/运行规则及 IPv6 原状，确认本次增量范围。

首版规则解析只接受明确的单个 TCP 端口规则及部分来源限制形式。
应用名称、端口范围、转发规则、未知语法、已存在的入口规则等会要求人工审查，不猜测或改写。
检测到已知地理阻断/ipset/Docker 链特征也会停止，不自动绕过大陆 IP 限制。

**这不是完整防火墙安全审计。** 不覆盖其他 nftables 表、legacy/nft 双后端并存、
所有自定义链的最终行为、云安全组及外部网络路径。新节点仍必须从客户端实际验证。
规则及来源地址不写入第二份长期快照，仅保存必要摘要与本工具新增规则的归属信息。

## 入口切换与启动

正式续期配置通过后，先停止本机试运行的 ShadowTLS。
确认既有配置身份和摘要，再原子替换其监听地址；两个密码及其他字段保持不变。
替换过程中临时文件权限为 `0600`，不跟随已有链接，也不覆盖已有候选文件。
正常完成后临时文件消失，中断时可能留下受限候选文件供人工核查。

确认 UFW 预期增量后才启动公网入口，再检查三项服务、监听范围、TLS 与证书。
通过后登记 Nginx、Snell、ShadowTLS 开机启动，再复查并写入完成记录。
只有 ShadowTLS 监听 IPv4 公网，两个后端仍只监听 `127.0.0.1`。

成功状态为 `public-enabled-external-test-required`。
这代表服务端配置通过本轮检查，不代表公网 DNS、云安全组、Surge 节点认证或实际应用测试已通过。
不自动重启服务器；关机再开机验收需要另行确认。

## 失败与重复操作

公网启用与续期启用均先写意图记录。失败或不确定结果保留现场，禁止自动重跑。
若已尝试切换公网入口，失败时尽力停止并禁用其开机启动。
停止或禁用失败会明确报告，不能宣称端口已关闭。

不盲删放行规则，因为命令超时可能已经完成操作；删除可能误伤原有或后来修改的规则。
已经正常启用的续期不会因后续公网入口失败而自动回滚。
如果续期启用本身失败，则尽力停止相关任务并禁用 timer。
保留本机后端和必要配置，不卸载包、不刷新防火墙，也不重生成密钥。

完成后的重复调用只复查，不重复添加规则、重启或签发。
发现配置、规则、服务覆盖或开机状态变化时停止；目前没有更新或自动恢复入口。
强制杀进程或断电时清理不一定执行，仍可能留下部分已启用的任务/服务，不能声称整批操作原子化。
不要与其他管理员、包管理或部署操作同时修改这些资源。

## 验证与下一步

公网启用批次完成时本地测试 249 项通过，本批新增 35 项；最新总数见项目 README。
包括 IPv4 规则实际增量、IPv6 不变、SSH 端口确认、重复执行、未知规则、
续期任务失败、规则添加结果不确定、入口失败、停止失败、外部文件修改及中断保护。
完整套件同时重跑了真实本机 TLS 测试。

APT、UFW、Linux 内核规则、systemd 及 CA 操作在本批中仍使用模拟器，
没有实际启用 VPS 端口或定时器，没有测试真实证书轮换。
上层实验安装入口、SSH 确认与失败诊断已串联；仍需在明确授权的干净 Debian 测试机上联调。
开发源码已提供于公开仓库；尚无正式版本或一键远程安装命令，见 [源码交付](source-delivery.md)。
