# 候选配置写入与恢复

当前是开发用离线沙盒，不是 VPS 安装命令。所有目标路径都会放在显式初始化的测试目录下面，
没有写入真实系统根目录的开关。不能直接把本模块接到生产安装流程后就宣布部署安全。

## 操作范围

- 只创建本项目的六个候选文件：Snell 配置、ShadowTLS 配置、Nginx 站点、两个服务文件和续期钩子。
- 不下载程序，不安装包，不签发证书，不读 Cloudflare Token，不执行服务或防火墙命令。
- 不更改已有节点的域名、端口或密钥；参数不同会停止，不作为更新操作执行。
- 沙盒文件归运行命令的用户所有，不要求 root。将来真实安装必须另行验证 root 身份及归属。
- 不验证真实端口占用、域名归属、证书有效性、服务启动或客户端连接。
- 同一沙盒只允许一个本工具操作持有写入锁。多个节点的端口冲突检测仍属未来系统安装前检查。

## 本地试运行

在项目目录执行，不使用 sudo。以下路径使用物理绝对路径；路径中的符号链接不会被跟随。
初始化只运行一次，已存在且非空的目录不会被自动接管。

```bash
mkdir -p runtime
python3 -m snellctl sandbox init --root "$(pwd -P)/runtime/demo"
python3 -m snellctl sandbox prepare --root "$(pwd -P)/runtime/demo" --domain node.example.net
python3 -m snellctl sandbox status --root "$(pwd -P)/runtime/demo"
```

再次运行相同的 prepare，会核对已有记录、内容、权限和所有者。完全一致时返回未更改，
不写文件、不生成新密钥。候选配置里的示例域名没有经过 DNS 验证，也没有实际证书。
`runtime/` 已被 Git 忽略，但这不阻止人为强制提交；不要上传任何生成文件。

输出不显示密钥，状态只显示节点标识、待处理状态和候选文件是否完整。
候选配置文件确实包含新生成的明文测试密钥，不能把“终端没有显示”理解成没有敏感文件。
`sandbox status` 返回 0 仅表示文件核对通过且没有待处理操作，不表示服务可用。

## 防止覆盖

根目录必须为当前用户所有、权限 0700，且有本工具初始化标记。
打开根目录及后续目录时逐级使用目录描述符和 O_NOFOLLOW，不解析符号链接。
已有目录权限不合要求时停止，不顺带 chmod 或接管。首次检查发现任何同名目标（含悬空链接）时停止。

候选内容先以独占创建方式写入受限准备目录，再校验并发布。单个文件发布采用硬链接，
目标已存在时操作失败，不使用会覆盖目标的 rename/replace。发布后、提交记录前再核对每个目标的文件身份。
既有同名、同内容文件也不能仅凭摘要被自动认领。

文件内容和相关目录操作均调用 fsync。该实现要求准备区与目标文件位于支持硬链接、目录 fsync
和 flock 的同一本地文件系统；不支持时停止并保留恢复材料，不偷偷改成不安全的复制覆盖。
这不是一次原子替换六个文件：提交前可能看见部分候选文件，因此目前只允许在不运行服务的沙盒中演练。

## 状态与恢复

最小状态目录为沙盒内 `.snellctl-state/`，权限 0700：

- `lock`：固定的 0600 锁文件，解锁只关闭描述符，不删除文件。
- `stage/`：本次尚未完成操作的候选文件。发布后暂时与目标共用同一个文件实体，不另存一套配置数据库。
- `pending.json`：0600 的恢复记录，只含格式号、节点名、参数摘要、文件路径、权限和 SHA-256 摘要。
- `nodes/<节点>.json`：同类非秘密归属记录；成功提交后保留，用来识别重复操作和外部修改。
- `record.next`：写入恢复记录或提交记录时的临时元数据；中断时可能保留。

状态记录不含 Token、证书私钥、配置正文或节点密钥。摘要不是秘密备份，无法用它恢复丢失的密钥文件。
状态记录由受限目录保护，不是能抵抗 root 篡改的签名证明。

| 中断位置 | 处理 |
| --- | --- |
| 准备文件未全部完成，尚无 pending 记录 | 没有发布目标；只能明确取消，再重新准备。不会猜测缺失密钥。 |
| pending 已保存，部分目标已发布 | 继续时重用已有候选内容；取消时仅删除与候选文件身份一致的本次目标。 |
| 节点提交记录已保存，清理尚未完成 | 仅完成清理。即使选择 rollback，也不会删除已经提交的节点。 |
| 文件被替换、权限变更、材料损坏或出现未知文件 | 停止并保留现场，不强制覆盖、删除或自动重建密钥。 |

先查看状态，再明确二选一。以下命令不是卸载命令：

```bash
python3 -m snellctl sandbox recover --root "$(pwd -P)/runtime/demo" --action resume
```

或：

```bash
python3 -m snellctl sandbox recover --root "$(pwd -P)/runtime/demo" --action rollback
```

取消后可能保留空的框架目录，不递归删除已有目录。成功提交后准备文件与待处理记录会清理，
只保留正常候选配置和非秘密归属记录。普通删除不是磁盘安全擦除，也不能承诺内存完全没有残留。

如状态文件本身损坏，程序不能可靠确认归属，会要求人工检查，而不是提供自动强制清理开关。
flock 只协调遵守本工具锁的进程；不防御同 UID 或 root 的恶意并发修改、挂载替换或磁盘损坏。

## 测试与剩余工作

本地测试覆盖重复执行、独立节点、符号链接、意外硬链接、错误权限、已有文件、发布时出现新文件、
磁盘满、fsync 失败、跨文件系统错误、损坏记录、准备/发布/提交/清理边界中断以及取消过程再次中断。
另用真实子进程提前退出验证恢复，用第二个进程验证锁竞争；这些不是实际断电或 Linux 文件系统验收。

将来接入真实安装前，还必须加入平台与所有权检查、端口/SSH 保护、下载验证、证书与 Nginx 配置检查，
按服务生命周期安排写入和启动。软件包安装、DNS 修改、证书签发不能由这个文件事务自动撤销。
既有节点更新需要另一套带受限备份的流程，本批仅处理新建候选文件。
