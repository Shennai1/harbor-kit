# 本地源码交付包

这是开发侧离线打包工具，不是远程安装脚本、正式 Release 或签名发行系统。
不下载、不上传、不运行测试，不安装或操作 VPS；只写入指定的新输出目录。
先使用独立开发环境的完整回归入口，再从已经审查的源码目录运行：

```bash
python3 -E -s -B -m tools.source_bundle --output /tmp/harbor-kit-delivery
```

父目录必须存在，目标目录必须不存在，包括空目录及断开的符号链接也不覆盖。
源码树内只允许输出到已有 work 目录下；失败保留部分输出，不自动清理或重试。
中断或非零退出的目录不能作为完成的交付包。生成成功仍须人工核对后才允许发布。

## 产物

- harbor-kit-source-<公开快照摘要>.tar.gz：仅包含公开白名单文件，统一位于 harbor-kit-source 目录下。
- manifest.json：逐文件大小与 SHA-256、公开快照摘要、归档大小与 SHA-256，以及未签名/未验证源码提交等明确状态。
- SHA256SUMS：归档与 manifest.json 的 SHA-256，可在交付目录使用 `sha256sum -c SHA256SUMS` 核对。

沿用公开导出器的限制和基础敏感模式检查，不自动纳入新文件或私人记录，不包含协议二进制。
归档按路径排序，移除本机用户名、组名和源文件时间，普通文件模式统一为 0644。
相同源码在相同工具链下不因输出目录或源文件时间改变而产生不同归档；不保证不同压缩库之间字节一致。
打包前后复查公开摘要；这是有限变动检测，不是全系统原子快照，也不防御恶意并发 root。

## 信任与发布边界

这里的源码快照不是 Git 提交号，归档也不是 GitHub codeload 自动生成的归档；两种归档的校验值不能混用。
工具不接受自称可信的提交号或测试通过标记，不把未经核对的本地文件冒充仓库提交。
正式交付时仍需单独核对远端固定提交与包内逐文件内容，记录对应关系，并对实际交付源码复测。
清单和校验值若一起被篡改，内部核对仍可能通过；它们不是独立签名、完整秘密扫描或安全审计。
校验文件应来自已核对的发布渠道；在建立信任前不要执行或直接以 root 解压不可信归档。
本工具没有自动执行、自动更新或发布权限，不据此提供一键部署命令。
另有针对 GitHub 固定提交自动归档的[下载与校验入口](source-fetch.md)，
它不接受本地源码包的摘要作为 GitHub 归档摘要。

本地打包工具已在[固定提交的云端检查](https://github.com/Shennai1/harbor-kit/actions/runs/44590773500)
通过 Python 3.11/3.13 回归，并经本地打包与逐文件核对；这不等于 VPS 验收。
发行签名、许可证和正式版本范围另行确定。
