# 升级包审查材料与失败核查

这是独立的实验审查入口，不是升级命令。仅支持本工具完整受管的 Debian 13 / amd64 main，
尚待该系统实测。不会安装菜单或快捷指令，也不能用于手工/第三方节点、部分安装或待核查更新。

## 命令及确认

在已审核源码目录中，由 root 在交互 SSH 终端运行：

```bash
python3 -E -s -B -m snellctl package-update-review --experimental
```

先确认联网检查：刷新独立官方索引、模拟依赖并复核当前状态。保留系统原有 APT 配置和索引，
不读 Token、证书材料或原始日志；读取节点配置和已安装包资料作内部核验，不输出节点秘密。
这一操作会写检查缓存，并非纯只读。请勿并行运行 APT、Certbot 或其他管理操作。

没有变化时正常结束，不下载同版本包，不为测试降级、重装或强制更新。
有变化时，仅接受既有有限组件的同上游版本 Debian 修订更新；新增依赖、降级、跨上游版本、
hold、Nginx/common 不配套等均停止。它不检查 Snell/ShadowTLS 新版本或证明安全补丁状态。

之后还有两次默认取消的 `[y/n]` 确认，仅 `y/Y` 继续：

1. 展示精确包名及前后版本，确认下载和读取新旧包控制资料。下载阶段再次刷新独立签名索引，
   重新推导相同变化范围；候选或依赖改变就停止。只下载，不安装或执行包内脚本。
2. 材料收集通过后，确认保存本机私有材料。拒绝只保留下载缓存，不保存脚本文本。
   保存前后复核包、索引、已安装控制文件、模块目录和受管状态，变化则不宣告完成。

没有 `--yes`、`--execute`、版本/URL/Token/自定义输出路径参数，也没有旧报告导入入口。
命令的额外执行限制拒绝软件安装、服务变更、Certbot、UFW 写入及任意子命令；
即使确认全部通过，也不会转入内部升级协调器。

## 材料和隐私

成功时终端显示本次自动生成的路径：

```text
/var/cache/snellctl/package-update/<随机编号>/review/material.json
/var/cache/snellctl/package-update/<随机编号>/review/complete.json
```

`review` 为 root-only `0700` 目录，文件为 `0600`，仅新建，不覆盖、跟随链接或认领已有目录。
`material.json` 包含新旧维护脚本、触发器和配置声明、差异分类、候选文件清单、权限与摘要。
脚本中的终端控制字符以 JSON 转义保留，不执行、展开归档或跟随包内链接。

完整材料可能包含管理员对旧包脚本的本地修改，因此**不要直接贴进聊天或上传**。
只分享终端最后的 JSON；它不包含脚本文本、任意包内路径、令牌或节点配置。
需要专家协助审查时，先在本机人工检查并摘取已脱敏的相关片段，不自动发送完整文件。

`complete.json` 只记录本次材料大小、摘要和精确包版本，明确标记未通过安全审计、未授权安装、
不可复用为安装输入。摘要和完成文件都不是签名、安全证明或持久审批。
读取或核对摘要成功，也不能替代维护脚本语义、触发器、配置冲突、模块及外部消费者的审核。
后续真正安装仍须基于当时重新核验的材料和独立授权，不能直接安装本次缓存中的包。

新增材料总量受限，解码限制见[包内容读取边界](package-update-execution.md#包内容与分阶段确认)。
材料和缓存按需生成，未实现自动保留期限或清理命令；多次检查会增加磁盘占用。
本轮失败不会自动删除不完整材料；没有成功结果时，不把存在的文件当成有效审查结果。

## 结果含义

| 结果 | 含义及下一步 |
| --- | --- |
| `package-review-material-saved-no-upgrade` | 私有材料和本轮完成记录核对通过；仍需人工审查，不得据此直接升级。 |
| `no-package-changes-no-upgrade` | 本次候选无变化；正常结束，不证明全部组件最新或安全。 |
| `cancelled-before-download` | 只做了前面的索引/方案检查，包未下载；服务不受本命令改变。 |
| `cancelled-before-material-save` | 包缓存保留，完整脚本材料未由本轮保存。 |
| `stopped-no-upgrade` / `interrupted-no-upgrade` | 查看 `phase` 及尝试/核验字段；可能有缓存或部分材料，但本命令没有安装、停机或恢复动作。 |

返回码：`0` 为材料完成或无更新，`130` 为取消/中断，`2` 为参数/交互条件不满足，`1` 为核查失败。
`host_changes_attempted=true` 在这里指缓存或审查文件写入，不表示执行过安装。
`material_saved_verified=false` 不表示磁盘上一定没有材料；写入中断时可能留有部分文件。
本机服务状态查询不替代公网节点、TLS、客户端使用或重启验收。

## 中断后的顺序

先确认刚才执行的是本页的材料命令，还是未来的实际升级流程。二者不能混用恢复方式。
保持 SSH 会话，确认另一终端能够新建连接，不为了排错直接重启。

先用已有的只读记录入口查看是否存在更新或其他管理操作的待核查状态：

```bash
python3 -E -s -B -m snellctl install-status --json
```

只中断了本页的材料命令，并且没有任何待核查管理操作、没有 APT/dpkg/Certbot 等其他任务运行时，
可以在原因修正后重新发起一次检查。新检查使用新编号，不继续写旧目录，不复用旧材料授权，
也不会替你清理缓存。不应通过反复执行来绕过候选变化、来源、权限或模块检查。

若存在实际升级的活动记录、独立后台安装任务，或无法判断是否已进入安装，**停止重复执行**。
可以只读观察服务，不要运行下列命令的 start、stop、restart 或 enable 变体：

```bash
systemctl --no-pager show nginx.service certbot.service certbot.timer \
  -p Id,LoadState,ActiveState,SubState,UnitFileState,MainPID,Job,Result,ExecMainStatus
```

不要仅凭 `ExecMainStatus=0`、当前 SSH 仍连着、主进程消失或计时器停用判断升级成功。
实际升级的后台任务需要与原提交、执行身份、完整包状态和保护记录一起核对。
当前还没有公开的实际升级执行、任务接续或通用修复命令，不手工拼装内部调用。

| 实际升级可能停留的位置 | 保守处理 |
| --- | --- |
| 进入维护但未确认提交 | 保留意图及启动保护，先确认是否提交过后台任务，不重新启动安装。 |
| 提交结果不确定或任务仍运行 | 不重提、不强制停止任务、不删除锁，不因前台超时推断后台失败。 |
| 后台命令退出成功、尚未恢复 | 仍须包状态/配置/TLS/续期验收；只有符合原受限接续全部条件的现场才可恢复。 |
| 部分恢复、重启、文件漂移或包状态异常 | 保留现场及历史，另行人工核查；不自动回退或冒充新的安装前基线。 |

不要直接解除服务 mask、删除 `policy-rc.d` 或状态/锁文件，也不要为了修复而直接执行
`dpkg --configure -a`、同版本重装、降级、全机升级或重新安装节点。
原始 APT/Certbot 日志可能敏感，先提供脱敏结果和最后阶段，不整份上传。
这些说明不是恢复授权，亦不保证当前节点或续期一定仍在运行。

## 验证范围

本地测试覆盖候选选择、真实协调代码串联的模拟下载/材料保存、单独确认、取消/中断、
权限/链接/文件变化、隐私和命令限制。开发测试未执行 Debian 真实包升级、云端 DNS 或 VPS 服务操作。
下一步先在授权的测试 Debian 上验证本入口；若无更新，只验收无变化分支，不人为制造升级。

查询控制资料使用 [dpkg-query 官方接口](https://manpages.debian.org/trixie/dpkg/dpkg-query.1.en.html)；
模拟和只下载语义见 [apt-get 官方说明](https://manpages.debian.org/trixie/apt/apt-get.8.en.html)。
官方工具参数不能替代本工具的范围限制、实际包审查或实机验收。
