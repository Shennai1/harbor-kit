# 原安装成功后的受限恢复

本入口已接入本地代码，尚未完成 Debian 真实升级后的恢复验收，也没有安装到 VPS 菜单或快捷入口。
它不是重新安装、继续未完成安装、部分恢复续跑或通用修复命令。

## 使用条件

先按[实际更新的中断说明](package-update.md#结果与中断)保留现场并只读查询原任务。
仅当原安装明确成功、恢复尚未开始时，才可能适用以下独立实验入口：

```bash
python3 -E -s -B -m snellctl package-update-resume --experimental
```

命令只从本机活动更新意图选择原任务，不接受任务编号、旧报告、目标版本、Token 或 `--yes`。
需要 root 及交互终端。缺少活动记录不会扫描历史或认领其他任务，也不表示节点健康。

以下条件必须同时成立：

- 原第二版提交记录、私有安装前基线、包/任务绑定、执行标记完整且未变。
- 仍是同一次开机，原后台执行身份一致，命令明确成功退出。
- 没有其他待核查管理操作；没有任何首次或部分恢复尝试记录。
- 精确包状态、原运行配置、凭据、证书、SSH/UFW 及原启动保护核对通过。
  不能将变化后的现场认作新的安装前基线；不能用失败、超时或缺失日志推断安装成功。

运行中、失败、结果不明、已经重启、记录缺失、现场变化或已经尝试恢复均停止。
仍使用原内部核验逻辑，详细约束见[内部受限接续](package-update-execution.md#内部协调及受限接续)。

## 确认与副作用

1. 确认先只读检查。读取受限配置、凭据和证书作内存校验，不显示秘密，不读原始安装日志。
2. 完整核查通过后，展示原更新包的版本变化，确认独立 SSH 新连接及恢复控制台可用。
3. 分别确认恢复服务、DNS 演练和正式自动续期。默认 `n`，仅 `y/Y` 继续。
4. 保持原协作锁，再次核对全部现场并比较确认前后绑定；变化则停止，不沿用批准。
5. 独占记录本次恢复尝试，再复用原安装后流程：检查包和配置、移除自身相应保护、启动 Nginx、
   核对本机 TLS、用现用凭据执行 DNS 演练与重载、更新包归属记录、恢复定时续期，最后核查。

本入口不刷新索引、下载或安装软件包，不重新提交后台任务，不更换节点密钥、端口、SNI 或 SSH/UFW。
DNS 演练会访问 Cloudflare/测试 CA、增删 TXT 并重载 Nginx；正式证书不因演练替换。
恢复定时器可能触发真实到期续签。本命令不自动重启。

确认前及确认过程中取消，不会开始恢复或解除保护，但安装已经发生，服务可能仍停用，需要及时处理。
一旦写入恢复尝试，后续中断即使尚未启动服务，也不允许第二次接续；失败保留剩余保护、记录和日志，
不自动回退或重复操作。协作锁不能阻止外部 root 修改，须避免并行 APT、Certbot 和其他管理操作。

## 判断结果

| 结果 | 含义 |
| --- | --- |
| `packages-restored-external-test-required` | 原安装后的本机服务及续期核查通过，仍需客户端实际使用及正常重启验收。 |
| `cancelled-before-restoration-guards-preserved` | 未完整同意恢复，未写恢复尝试，未由本命令改变原服务及保护。 |
| `inspection-required` | 原任务或现场不满足条件，不自动修复或重试。 |
| `interrupted-inspection-required` / `stopped-inspection-required` | 需结合最后阶段、尝试标志和原记录核查，不能直接重复执行。 |

`host_changes_attempted` 表示已尝试写恢复意图，不证明服务已恢复；
`installation_submission_attempted` 始终为 false，本入口没有安装任务提交能力。
`upgrade_completed` 始终为 false，不能以本机核查代替外部验收。
返回码 `0` 表示本机恢复通过，`130` 为取消/中断，`2` 为缺少实验开关或初始非交互终端，`1` 为待核查。
本机私有结果文件只在恢复尝试已经记录后保存；无保存记录不等于没有发生操作。
若内层恢复结果保存中断，外层报告仍保留其已确认的完成字段及未确认的保存状态，
整体报告为中断待核查；即使已有完成记录，也不自动改报成功或再执行一次恢复。

仅分享最后的脱敏 JSON，不上传原始日志、运行配置、Token 或私钥。
不要删除保护/标记、重新执行安装、强行启动后台任务或以重启代替核查。
本地回归测试不操作真实 VPS，不代表真实软件包维护脚本或断线恢复已通过验收。
