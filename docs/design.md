# 设计约定

## 部署边界

管理官方程序和配置，不自行实现 Snell/ShadowTLS 协议与加密。
首版面向新的 Debian 12/13、x86_64/ARM64 VPS；按测试结果缩小或扩展支持范围。
首个候选组合是 Snell v5 + ShadowTLS v3 + 本机 Nginx，具体程序版本在实机验证时固定。
协议版本与程序发行版本分别记录。

不实现第三方节点迁移，不默认创建网页管理端口。不自动运行未知的一键脚本。
检测到旧服务时说明冲突，由用户决定处理；安装器不覆盖不属于自己的文件。

## 运行配置与隐私

服务配置是运行依据；少量管理信息可记录安装来源、版本和配置格式，不复制完整秘密数据库。
每次新部署生成独立随机凭据，不随重启或普通更新重新生成。
凭据权限按读取该文件的服务身份配置；诊断不读取密码、Token 或证书私钥。

配置、证书和凭据按归属隔离，证书不能因另一域名续期而被覆盖。
域名、端口和服务名不是秘密，但公开诊断默认不暴露具体 IP，域名在后续报告中应可打码。
不给 GitHub 或第三方上报运行配置；公开仓库不包含历史笔记中的私人节点细节。

备份仅在变更期间保留，失败/中断时不提前清理恢复材料。不能声称普通删除等同物理安全擦除。
长期备份另行选择。系统与组件日志分别设置保留策略，不能承诺整台系统完全没有日志。

本地文件事务先在显式初始化的受限沙盒中验证，只新建候选文件、不覆盖已有节点。
以非秘密摘要记录归属和重复操作，以准备文件的身份核对恢复范围；成功后不保留第二份秘密配置。
多文件发布不等于全局原子部署，不能把文件恢复扩展为包安装、DNS 或证书签发的自动撤销。
现有节点更新、共享资源卸载及真实系统写入必须另行验证。

## 管理入口

节点管理负责协议组合、协议版本、PSK、ShadowTLS 密码、公网端口、域名关联和客户端配置。
域名/证书管理负责 Nginx TLS 站点、ACME 签发续期、Cloudflare 凭据和 DNS 检查。
Cloudflare Token 属于 DNS 验证工具使用的凭据，Nginx 本身不使用它。
管理界面默认隐藏秘密；需要的客户端秘密仅在用户主动查看或导出时显示。

公网入口、Snell 后端、Nginx 本机端口各有独立角色，不能根据端口号猜测用途。
IPv4/IPv6 本机监听检查不等于公网连通性检查。防火墙、云安全组和外部连通性分别验证。
本机监听的 Nginx 可经 ShadowTLS 间接接收外部流量，因此仍需安全更新。
当前新机验证路线采用 Debian 标准 nginx.service 与本工具独立的 conf.d 站点文件，
不创建第二套 Nginx 实例或覆盖全局配置；已有站点的机器不自动接管。
Nginx 指令按实际版本选择，不能把 1.26.x 的 http2 on 直接应用于 1.22.x。

## 更新边界

- 管理工具：本项目的正式版本。
- Snell：Surge 官方下载服务器。
- ShadowTLS：官方 GitHub Releases。
- Nginx：首版优先 Debian 软件源和安全更新；换源作为独立迁移操作。
- ACME：测试 VPS 已选用 Debian Certbot + Cloudflare DNS 插件，使用 Debian 源更新；
  不能让两套工具同时管理同一路径。凭据仅由证书工具读取，Nginx 不读取 CF Token。

不将 `latest` 自动等同兼容；缺少来源验证时不能静默降级到禁用 TLS 校验。
软件检查更新不等于允许自动切换协议大版本。
证书自动续期，服务重载；程序更新需要验证运行中的进程已加载新程序。
APT 更新须考虑相关已安装模块/软件包，不比较上游短版本号来推断 Debian 补丁状态。

## 后续待验证事项

- Snell v5 组合的手工 IPv4 节点可用性、下载和 TCP 实际应用已验证；普通 UDP、QUIC Proxy Mode 和 IPv6 尚未验证。
- ShadowTLS 0.2.25 配置、非 root 运行、本机 TLS 与 Surge 实际应用已验证；错误密钥负向检查未完成。
- 手工基线的三项服务及 UFW、证书定时器的开机恢复已验证，开机后 Surge 延迟与实际使用也通过。
- Nginx 回环监听、SNI 拒绝及当前证书加载已通过实机验证；程序更新后的运行验证仍待完成。
- ACME 初次签发、模拟续期、Nginx 部署钩子及重载后复查已通过；正式证书轮换和故障展示仍待验证。
- 安装器已接入有限 UFW 增量放行，仍待整机实测；地理 IP 阻断作为独立扩展，不放入首版默认安装。
- 发布的下载完整性、来源验证和签名密钥更新方案。
