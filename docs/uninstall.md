# 受管节点卸载（实验版）

仅限本工具完整管理且目前健康的 Debian 13 / amd64 / IPv4 TCP 单节点 main。
正常流程已有用户实机反馈；不是对手工或第三方部署的卸载工具，仍属实验功能。
不要直接使用已发布旧版本运行不存在的命令。菜单和永久快捷入口不变。

## 授权和最终状态

经审核、确认交付的含本功能固定版本提供独立入口：

```bash
python3 -E -s -B -m snellctl uninstall --experimental
```

只能在交互终端使用，先只读核查，再分别用默认 n 的 `[y/n]` 确认四项内容：
资源没有其他消费者；独立 SSH 新连接和恢复控制台可用；接受最终停用状态；允许不可撤销停机删除。
不接受自动 yes、域名、路径、Token 或 root 参数。目标从经过核对的现用配置派生，不固定用户域名或端口。
只读预检查通过不是本入口的授权；确认期间有任何变化便停止，不以此前输出替代现场复核。

成功后的边界：

- 停止并禁用两项节点服务和 Nginx；删除两个专用服务文件及对应节点配置。
- 停用 Certbot 定时器并保持停用，不停止正在执行的 Certbot，不自动恢复通用续期任务。
- 移除受管 Nginx 站点、部署钩子、续期服务覆盖、当前单域名证书组、独立本机 CF 凭据和两个版本化程序。
- 仅删除有归属记录且唯一匹配的 IPv4 TCP 入口规则，核对 SSH 和全部其他已观察规则保持不变。
- 保留 UFW、本机软件包及供应商配置/服务、内核/APT、ACME 账户、历史日志和受限管理记录。
- 不删除云端 DNS，不撤销 CF Token 或证书。空目录也保留，不递归清除全局目录。

禁用不等于 mask，其他管理员、依赖或后续软件包操作仍可能启动服务；本功能不承诺永久禁止外部启动。
检查只覆盖有限范围和当前规则，不证明没有外部脚本、容器或其他消费者，仍需操作者确认独占用途。
保留历史是为了核查中断及部分删除，不是已经恢复为新机：`reinstall_ready=false`。
不允许通过删除状态目录来绕过后续重装审查，目前没有卸载恢复或重装执行入口。
另有独立的 [卸载后只读重装预检查](reinstall-plan.md)，通过不表示可以重装。

## 执行顺序

1. 在既有协作锁内重复健康/归属/目录/共享引用检查，额外核对 Nginx 供应商服务文件的包内摘要。
2. 在第一次外部操作前写入 root-only 卸载意图；新建独立日志/结果目录，不覆盖其他操作历史。
3. 停用续期定时器，沿用已有 90 秒有界等待，要求两次空闲采样；不强停 Certbot。
   续签引起证书快照变化也会停止，不自动接受新快照或继续删除。
4. 停止并禁用 ShadowTLS、Snell、Nginx，分别核对运行/开机状态、主进程及控制进程、任务为空。
   再核对原端口及组件均无监听；命令返回成功不能代替这些检查。
5. 用完整 IPv4 规则删除唯一工具入口，不用可变编号；复查其余规则及 SSH 监听。
6. 先解除 Nginx 站点和部署钩子引用，检查剩余 Nginx 配置；然后只对明确的当前证书名称运行 Certbot delete。
   保留受管续期覆盖直到证书删除已核对，且要求原 live/archive/renewal 三条路径全部消失。
7. 删除独立凭据、其余受管配置/程序/专用服务及续期覆盖；逐文件检查身份、内容和元数据。
8. 刷新 systemd，核对专用服务已不存在、Nginx 和续期仍停用、组件无监听及 SSH/其他规则未变。
9. 写入完成记录后才清除活动意图；保留历史和独立结果文件，不自动启服务或重启主机。

受管文件只用核对后的固定路径和 inode 身份删除。每次普通文件删除前落盘尝试记录；
证书删除由 Certbot 负责，不手工遍历删除 `/etc/letsencrypt`。
同时复查 Certbot 全局配置及隔离 HOME；确认后新增或修改配置会停止后续删除，保留外部改动。
执行器限制系统命令，只允许已有只读核查和当前一次明确授权的操作；不调用软件包或清空防火墙命令。
协作锁和快照无法阻止不遵守协议的外部 root；禁止与其他管理或 Certbot 操作并行。

上述证书顺序参考 [Certbot 安全删除说明](https://eff-certbot.readthedocs.io/en/stable/using.html#safely-deleting-certificates)。
禁用与停止、隐式刷新等行为参考 [systemctl 257 文档](https://www.freedesktop.org/software/systemd/man/257/systemctl.html)。

## 中断和结果

失败后不自动回退、启用续期、重启节点或重试删除。节点可能部分停止，文件可能部分删除；
自动续期可能停用，必须及时核查，不能把现用节点继续工作的旧经验用于卸载中断。
活动标记阻止配置导出和后续管理。成功也保留完成标记，阻止把旧安装记录误当成当前运行状态。
`install-status` 只读报告 `uninstall=needs-inspection` 或 `completion-recorded`，不代替现场健康检查。

变更阶段不持续向终端输出，CLI 暂时忽略普通 SIGHUP；强制终止、系统会话清理、断电仍可中断。
退出时恢复原信号设置，捕获到异常停止后续动作。没有后台恢复机制或通用断点续跑。
最终输出失败不能通过重复执行补救，应重新连接后查看记录。

`managed-node-uninstalled-history-preserved` 与 `final_state_verified=true` 表示本次最终本机检查通过；
各 `*_attempted`/`*_verified` 表示执行阶段的证据，不是之后永不变化的保证。
失败时 `final_state_verified=false`，即使之前某个阶段的 verified 为 true，也不能当作最终状态通过。
软件包、历史及其他保留范围仍在，不是磁盘数据擦除，也不证明云端已撤销权限或无备份副本。

`report_saved=false` 时保留终端 JSON，不能重跑来补日志。
新目录位于 `/var/lib/snellctl/preparation/uninstall-*`，仅 root 可访问；
其中可能包含域名、受管文件路径、摘要或 Certbot 自身日志，不分享原始文件，只分享脱敏 JSON。
预检查不读取外部秘密；卸载会读取现用秘密作内存核验，但不向报告输出密钥、Token、指纹或完整路径。

用户实测已覆盖正常卸载、卸载后的服务/启动配置、防火墙和监听检查及独立 SSH 新连接。
其中一次真实观察到 Certbot 短暂忙碌后自然结束，再完成卸载；不代表全部竞态已验收。
尚未覆盖卸载后重启、所有外部并发、断电时刻或失败恢复；本地故障模拟不能代替这些验收。
后续另行实现已卸载主机的受控重装；发布源码本身不要求用户立即执行卸载。
