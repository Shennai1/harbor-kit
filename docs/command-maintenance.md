# 管理工具自身维护

管理代码维护已发布；更新、移除及重新安装正常路径已有 Debian 13 / amd64 用户实测通过反馈，
各阶段用户另行确认节点实际使用正常。中断接续、自动回退及其他平台不在该验收范围内。
这不是 Snell、ShadowTLS、Nginx 或其他节点组件升级，也不是节点卸载。

## 入口与授权

仅支持 root、Debian 13 / amd64、Python 3.11 或以上。先单独下载经过审查的固定提交，
核对归档摘要，再在该外部源码目录的交互终端运行相应入口：

```bash
/usr/bin/python3 -E -s -B -m snellctl update-command --experimental
/usr/bin/python3 -E -s -B -m snellctl remove-command --experimental
```

以上是两个独立操作，不能连续粘贴执行。安装目录里的快捷命令不能用于替换或移除自身，
也没有加入菜单；必须保留独立源码，以免维护中入口不可用时失去核查手段。
没有 URL、任意目标目录、指定版本、自动确认、自动重试、接续或自动回退参数。
不自动下载最新版本，不把本地清单当作作者签名或安全审计。

确认前和确认后都核对已安装代码、权限、文件清单和候选源码；两次 `[y/n]` 确认分别覆盖
无并发管理及备用 SSH、代码替换或永久移除。默认取消，只有 y/Y 继续。
候选与现用运行代码相同时不写入，返回 `command-already-current`。
这里是操作员审查后的代码替换，不作版本新旧、安全补丁或禁止降级的判断。

## 范围与结果

- 固定管理目录 `/usr/local/lib/harbor-kit` 和入口 `/usr/local/bin/snellctl`。
- 固定暂存目录 `.new`、旧代码目录 `.previous`、维护标记 `.intent.json` 位于管理目录同级，
  原子入口替换可短暂创建 `/usr/local/bin/snellctl.snellctl-new`。这些名字不是节点资源。
- 只接受当前模块布局且清单/权限核验通过的安装，以及公开提交 `2409683` 的精确旧运行快照。
  旧版兼容清单和摘要固定；其他旧布局不能按文件名推断归属，不读取或执行旧安装中的任意代码来验证。
- 更新先写候选并复核，临时将命令替换为拒绝启动的提示，再切换目录。新代码核对后删除旧代码，
  恢复入口并移除标记；成功返回 `command-updated`。没有保留可用的回滚副本。
- 移除使用固定清单逐个删除已核查的文件，不递归清空目录；删除入口及空管理目录后返回
  `command-removed`。父目录保留，随后状态应为 `not-installed`，允许单独重新安装管理工具。
- 不读取节点密钥、CF Token、证书或 ACME 账户，不执行 APT、Certbot、systemctl、UFW 或联网操作。
  `/opt/snellctl`、`/etc/snellctl`、节点历史、服务、证书、软件包及防火墙均不在处理范围内。

## 并发及中断

新版启动器在 `/usr/local/lib` 目录 inode 上持有共享 advisory flock，外部维护持有独占锁，
使用非阻塞方式；存在打开的新版管理会话时拒绝维护。这不创建持久锁文件，也不是系统全局锁。
锁覆盖新版快捷入口进程，不覆盖第三方脚本、直接从旧源码运行的命令或外部 root 操作。
`2409683` 的旧启动器没有协作锁，首次更新前尤其需要人工退出全部旧菜单和管理操作。
不能仅凭取得锁证明没有其他进程或消费者；本工具不强制结束任何进程。

任何维护暂存/标记残留都会阻止新维护、首次安装及新版快捷入口启动；不自动删标记或恢复。
旧版快捷入口在还未切换时不能识别新维护标记，因此中断后不要继续使用它运行管理操作。
失败可能发生在旧代码尚完整、快捷入口已阻断、部分删除或新代码已切换等不同阶段；保留所有现场。
输出仅显示阶段和脱敏结果，不显示原始异常。不要直接再次执行更新/移除或手动清空目录。
外部核验源码的 `command-status --json` 可报告代码状态，但不修复现场、不表示节点健康。

成功后需要新 SSH 中的状态/菜单验收，并另行验证节点实际使用。取消、失败注入与本地沙盒测试
不能替代 Debian 上真实的更新、移除和安装恢复验收；本轮不要求用户修改 VPS。
