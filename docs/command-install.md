# 永久快捷命令首次安装

首次安装、新 SSH 呼出、代码核对及普通菜单查询/取消已有 Debian 13 / amd64 用户实测反馈；
不代表全部菜单操作或本轮新增维护能力已验收，也不是本轮已经发布新版本的通知。
仅支持 root、Debian 13 / amd64、系统 Python 3.11 或以上。无需网页面板或额外端口。
只安装管理代码，不部署节点，不执行 APT、Certbot、systemctl 或 UFW，不读取节点凭据。

## 使用边界

先取得经过确认的固定提交源码，并核对归档 SHA-256；不要执行未知来源或可被其他用户修改的代码。
在该源码目录的交互终端运行：

```bash
/usr/bin/python3 -E -s -B -m snellctl install-command --experimental
```

显示范围后用 `[y/n]` 确认，默认取消，仅 y/Y 继续。没有 `--yes`、自定义路径、URL 或覆盖选项。
来源摘要只能核对内容，不是作者签名或安全审计。工具不替用户从任意源码建立信任。
安装前以及确认后重新读取固定文件清单，内容改变即停止；不复制整个工作目录。

安装成功后，在新的 SSH 终端中可使用：

```bash
snellctl
snellctl command-status --json
snellctl menu --experimental
```

无参数进入普通查询菜单；实验菜单也只显示入口，各项操作仍有原有核查和独立确认。
`command-status` 默认和 `--json` 都输出 JSON，只检查管理代码，不表示节点或公网健康。
如果 PATH 未包含 `/usr/local/bin`，可以显式使用 `/usr/local/bin/snellctl`；不自动修改 shell 配置。
工具检查当前 PATH 和常用系统路径中的同名可执行文件，但不检测交互 shell 的 alias、function 或缓存。
出现同名入口时先调查来源，不能通过删除其他工具来绕过冲突。

## 文件与归属

| 路径 | 用途 |
| --- | --- |
| `/usr/local/lib/harbor-kit` | 独占管理代码目录，0700 |
| `/usr/local/lib/harbor-kit/snellctl` | 固定 Python 模块集合，目录 0700，文件 0600 |
| `/usr/local/lib/harbor-kit/launcher.py` | 独立启动前校验器，0600 |
| `/usr/local/lib/harbor-kit/manifest.json` | 本地代码清单及摘要，0600，不含节点秘密 |
| `/usr/local/bin/snellctl` | 固定 shell 入口，0755，最后创建 |

目录和文件须由 root 持有，上级目录不能允许其他用户写入；拒绝符号链接、硬链接和异常文件类型。
入口固定调用 `/usr/bin/python3 -I -B`，忽略当前目录和 PYTHONPATH 等 Python 环境路径，禁写字节码。
启动前核对固定清单、内容摘要和权限，拒绝额外模块、缓存目录或缺失文件，再导入管理代码。
校验器及本地清单本身依赖 root 信任；不能防范恶意 root、被篡改的解释器或并发 root 操作，
也不是全系统原子快照。不能把本地清单称为独立签名验证。

现有目标无论完整、残缺还是空目录都拒绝，不覆盖、不接管；失败后不删除现场或自动接续。
不复制 README、测试、私人笔记、日志、节点配置、CF Token、证书或密钥。
安装目录独立于 `/opt/snellctl`、`/etc/snellctl` 和节点历史目录。
节点卸载/重装不会删除或更新这套快捷入口；管理代码也不会自动跟随 GitHub 变化。
管理代码更新及移除已另行本地实现，须从外部核验源码运行，尚待发布和实机验收，
见 [管理工具自身维护](command-maintenance.md)。没有中断恢复入口，不能直接重跑首次安装。
新版启动器与维护使用协作锁，发现相邻维护标记/暂存目录会拒绝启动；不自动修复。

## 中断与检查

写入之前取消不会安装。写入后可能只留下部分目录，或入口已经存在但最终核对未通过。
即使报告失败，也不要假定所有文件都不存在；不要覆盖、手动清空或重新执行安装。
可以从独立核验的源码运行 `python3 -E -s -B -m snellctl command-status --json`，
避免依赖可能损坏的已安装入口。只报告 `not-installed`、`installed-code-verified` 或待核查状态。
状态检查不执行修复、联网、服务操作或持久报告写入。

后续实机验收应分别检查首次安装、退出临时目录后的启动、新 SSH 中的命令查找、
普通/实验菜单及取消操作，再确认原有客户端仍可使用；不为测试破坏线上代码或重复变更节点。
本地文件系统、隔离子进程及失败注入测试不替代这些验收。
