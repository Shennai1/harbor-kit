# 公网入口端口更换

实验入口，仅用于本工具完整部署、当前检查通过的单节点 main。
首版限定 Debian 13 / amd64 / IPv4 TCP。已做本地模拟测试，尚未做 VPS 端口更换实测。
不会接管第三方或手工节点，不用于调整 SSH 或两个本机后端端口。

## 操作入口

取得已核对的固定版本源码，在源码目录的 root 交互终端执行：

```bash
python3 -E -s -B -m snellctl change-port --experimental
```

也可以使用 `python3 -E -s -B -m snellctl menu --experimental` 的菜单 9。
普通菜单不显示该操作，不接受端口命令行参数、管道输入或自动确认。

输入新端口后先只读检查，显示当前/目标公网端口及应保留的 SSH 端口。
保留当前 SSH，通过不依赖此节点的网络另开 SSH，确认新连接和恢复控制台可用。
确认“已重连”后，还须输入含目标端口的完整确认语，例如“更换端口 24443”。
示例不是固定端口；新的端口可在 1 至 65535 内选择，但须通过全部冲突检查。
直接回车或其他确认内容均取消。执行前会重新检查，不把此前检查当作预约占用。

## 变更范围

- 保持两项节点密钥、证书域名、CF Token、证书、Nginx/Snell 本机端口不变。
- 仅替换 ShadowTLS 的公网监听端口。跨越 1024 时，同时增减该服务的低端口绑定权限，
  验证 unit、重新加载 systemd 配置并核对实际加载的能力集合。
- 通过 UFW 新增明确限定 IPv4 的 TCP 放行，不新增 IPv6/UDP 业务规则。
- 新入口启动、本机 TLS、证书和监听验证通过后，再按完整 IPv4 规则删除原入口的放行。
  不按会变化的规则编号删除，不修改 SSH 规则，不运行 UFW reset/disable/reload。
- 成功后更新当前归属清单和客户端端口；不会保存另一份含密钥的备份或完整配置数据库。

本机检查不等于公网可达。云安全组、服务商端口限制及外部网络由用户另行确认；
删除旧放行前没有自动外部客户端测试，也不保留双端口并行服务。
操作会中断节点连接。应使用独立 SSH，不能以待修改节点作为唯一管理通道。

## 检查与记录

先核对部署完成记录、文件身份和内容、模板、证书、服务、绑定能力、续期任务及 UFW。
拒绝相同端口、SSH/后端端口冲突、新端口已有 TCP/UDP 任一地址族监听、已有规则、
无法识别的规则、地理阻断链、配置漂移、其他待处理变更及遗留候选文件。
只有本工具当前记录所匹配的唯一旧规则可以被删除。
UFW 的保存规则和运行链须一致；每一步复查 SSH、原有规则及 IPv6 内容是否保持。
这是有限核查，不是全部 nftables 表、内核规则、云安全组或并发 root 操作的完整审计。

开始写入前，在 `/var/lib/snellctl/preparation/port-change-intent.json` 保存 0600 待核查记录。
只含格式、前后参数摘要与旧/新端口，不含域名、IP、Token、配置正文或密钥。
该标记存在时，当前版本的客户端导出、密钥更换、端口更换和公网启用均拒绝继续。
`install-status` / `cleanup-plan` 会提示待核查；不要删除标记或使用旧版代码绕过。

当前的 `public-files`、`public-ready`、`public-firewall-added`、`renewal-test-ready`、
`renewal-enable-ready` 会在成功时更新。后两项只把已验证的续期兼容记录关联到新参数：
证书、DNS、续期钩子和定时任务内容未变；这不表示重新演练、重新签发或实际到期续签。
初次安装的意图/激活记录保留为历史，不拿它们恢复旧配置。
五份记录不是同时原子写入，完成前由待核查标记阻止正常读取；全部核对后才删除标记。

## 失败边界

进入变更后发生错误或可捕获中断，会尝试停止并禁用 ShadowTLS 入口，保留标记及现场。
不会回退到旧端口，不会删除不确定是否已添加的规则，不会恢复旧配置或重置防火墙。
因此可能留下旧、新两条放行，也可能已删除旧规则；不能根据错误提示猜测当前规则。
Snell、Nginx、SSH、UFW 及证书定时器不作为失败清理对象。
若停止、禁用或记录本身失败，明确标记结果不确定，不能保证入口已关闭。

断电、SIGKILL、远端进程异常终止可能绕过错误处理。持久标记不等于开机自动停用保护；
启动中的新/旧配置和规则可能已部分生效。尚无自动回退或通用恢复入口。
失败后保留 SSH，查看脱敏记录，人工核对服务、监听和规则；不要盲目重跑、重启或清空 UFW。

## 实机验收

以下项目仍待授权测试 VPS 的结果，不把本地模拟结果填写为通过：

1. 用独立 SSH 和可用控制台，选择未被使用且服务商允许的新端口。
2. 入口只在新 IPv4 TCP 端口监听，后端继续回环；原工具规则消失、新规则唯一，SSH/IPv6 不变。
3. Surge 只修改公网端口，保留原两项密钥及 SNI，重新测试延迟和实际连接；旧端口不再作为此节点工作。
4. 低/高端口切换时检查非 root 服务权限和实际监听；成功后可另行测试换回，不能作为失败后的自动恢复方式。
5. 端口变更与此前密钥更换的当前记录相容，导出反映当前端口；确认服务及续期定时器的开机登记仍在。
6. 如安排正常重启验收，先确认没有待核查标记，再检查服务、规则、监听与实际客户端恢复。

本地测试覆盖高/低端口转换、重复成功更换、与密钥更换交替、保持秘密和 SSH、
确认取消/过期、占用/规则冲突、TLS 失败、UFW 不确定结果、文件写入和清单提交失败、
外部修改保护、异常清理及导出阻断。系统管理、UFW 与此流程的 TLS 探针均为模拟依赖；
项目另有真实本机 TLS 探针测试，但不能代替 Debian 服务与 UFW 的联动实测。

实现依据：[UFW 完整规则、删除与 IPv4/IPv6 语义](https://manpages.debian.org/trixie/ufw/ufw.8.en.html)、
[systemd 能力设置](https://manpages.debian.org/trixie/systemd/systemd.exec.5.en.html)、
[systemctl 配置重载](https://manpages.debian.org/trixie/systemd/systemctl.1.en.html)。
