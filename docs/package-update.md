# 实验版实际软件包更新

此入口已经接入本地代码，但尚未完成 Debian 真实升级、断线及恢复验收。
不是菜单或快捷命令安装，也不提供通用修复、自动回退或自动重试。只用于明确授权的可恢复测试机。
与 `package-update-review` 不同，它具有停机和实际安装能力；不能因为上次无更新检查通过就直接批准全部步骤。

## 范围与确认

`package-update --experimental` 仅适用于完整受管 Debian 13 / amd64 main。
基于当时的新官方签名索引和本机状态检查，不接受旧报告、缓存编号、用户指定版本或 `--yes`。
现有组件同上游版本的有限 Debian 修订升级范围见[更新基础](package-update-execution.md)。
不更新 Snell/ShadowTLS，不改节点密钥、端口或 SSH/UFW；不处理新增依赖、模块或跨上游版本更新。

流程均为交互 `[y/n]`，默认取消，仅 `y/Y` 继续：

1. 确认联网检查并写入独立缓存。无候选变化就结束，不创建安装任务、不下载同版本包或停机。
2. 展示本轮版本，确认下载；再次刷新索引、核对相同范围并校验包。
3. 确认保存 root-only 材料，再在另一 SSH 会话阅读新旧维护脚本、控制资料、差异分类和候选文件清单。
   工具不作脚本语义安全审计。只有已独立审查并接受内容才确认；无法判断必须选 `n`。
   材料可能含本地敏感内容，不直接上传或粘贴进聊天；格式和路径见[材料说明](package-review.md)。
4. 分别确认独立 SSH/恢复控制台及维护停机、精确版本安装。两项都同意后才停止 Nginx、暂停续期并建立保护。
   重新核对包、旧控制资料、模块以及本轮展示文件的内容、身份和权限；变化则停止，不沿用批准。
5. 提交一次固定后台任务，前台有限等待原任务结果；不能因为前台超时或断线而再次安装。
6. 原任务明确成功后，分别确认恢复核查、DNS 演练、正式自动续期，三项都同意才开始恢复。
   DNS 演练会使用现用 CF 凭据，访问 Cloudflare/测试 CA 并增删 TXT；恢复定时器可能触发正式到期续签。

前面的联网检查和材料收集不读取 CF Token 或证书。进入维护核查和恢复后会读取受限运行凭据及
证书作本机校验，不输出内容。请勿并行运行 APT、Certbot 或其他管理操作。

材料完成文件不是批准凭证，实际审查确认只绑定本进程、本轮材料；不能导入、复用或从文件自动批准。
允许 root 运行的维护脚本可能影响未列出的资源，启动保护不是隔离任意脚本副作用的沙箱。
协作锁及前后检查不能阻止外部 root 并发修改，必须安排独占维护窗口。

## 结果与中断

| 结果 | 含义 |
| --- | --- |
| `no-package-changes-no-upgrade` | 本次范围内候选无变化；未进入停机或安装，不代表全机最新或安全。 |
| `cancelled-before-download` | 没有下载本轮包；前面的检查缓存可能保留。 |
| `review-not-approved-cache-preserved` | 未同意材料保存或未确认独立审查；不进入维护，已有缓存/材料保留。 |
| `cancelled-before-maintenance-cache-preserved` | 停机或安装确认被拒绝；本轮未进入维护。 |
| `packages-restored-external-test-required` | 安装后本机及续期核查通过；仍需客户端实际使用及独立重启验收。 |
| `restoration-not-authorized-inspection-required` | 已安装，但未完整授权恢复；Nginx/续期可能仍停用，须及时核查。 |
| `stopped-inspection-required` / `interrupted-inspection-required` | 根据维护、提交尝试及最后阶段核查；不得重复执行或自动解除保护。 |

`installation_submit_attempted` 表示已进入提交步骤，不等于命令肯定启动或包安装完成。
`operator_review_confirmed` 是操作者的确认，不是工具独立审计结论；`security_audit_passed` 仍为 false。
`upgrade_completed` 保持 false，不能以内部通过代替外部客户端和重启验收。
返回码 `0` 为无更新或本机恢复完成；`130` 为取消/中断；`2` 为参数/终端条件不符；`1` 为待核查失败。
退出码不能替代报告阶段，例如取消恢复并不撤销已发生的安装。

提交或恢复的结果保存被中断时，返回报告仍保留中断前已确认的尝试、提交和完成字段，
但相应 `report_saved=false`，整体结果为待核查中断。它表示保存未确认，文件也可能已经写入；
不能据此重新安装或重复恢复。上层报告保存成功也不能替代内层结果文件的保存状态。

中断后先确认新的 SSH 连接仍可建立，**不要重跑更新、重启、强停后台任务或删除保护文件**。
在同一份已审核源码目录运行只读查询：

```bash
python3 -E -s -B -m snellctl package-update-status --json
```

它只根据现有活动意图读取原任务，不接受用户任务编号，不扫描全部历史，不读原始 APT 日志或秘密，
不安装、不恢复、不写入记录、不改变服务。它校验原提交记录、执行身份和文件绑定，再查询 systemd。
执行标记必须符合原启动器生成的规范格式；重复字段、非整数格式编号等异常记录均停止核查，
不自动修正或重建。这是记录完整性检查，不是防御拥有 root 权限的操作者。

- `running-or-queued`：原任务仍在运行/排队，保留现场等待；本命令不会停止它。
- `command-exited-success`：只证明绑定的原命令成功退出，不代表包/配置/TLS/续期验收完成。
- `command-exited-failure`：原任务失败；不重新执行 APT、`dpkg --configure -a`、重装或降级。
- `execution-not-proven-do-not-resubmit` / `inspection-required`：身份、记录或状态不足，不能推定从未安装。
- `no-active-update-record-not-a-health-verdict`：没有活动记录，不证明升级成功、节点健康或不需要恢复。

如果另一管理流程仍持锁，查询会停止，不删除锁或干预原流程。部分提交、部分恢复、开机变化、
文件漂移、无法确认结果等需要单独核查，不能自行拼装内部调用。
另有[实验版受限恢复入口](package-update-resume.md)，只支持原任务明确成功且恢复尚未尝试的
同次开机现场。它先核查再分别确认，不重新安装、不续跑部分恢复，也不保证任意中断都能恢复。

本地模拟回归不等于 Debian 安装验收。后续先审定这一批，再交付固定源码版本；
真实升级只在有受支持候选和明确维护授权时测试，不为了测试而降级、同版重装或强制更新。
