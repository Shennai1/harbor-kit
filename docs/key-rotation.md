# 单独更换节点密钥（实验版）

仅用于本工具完整部署、已开放且当前检查通过的 main 节点。
首版限定 Debian 13 / amd64 / IPv4 TCP；不接管手工或第三方脚本节点。
此入口已通过本地模拟测试，尚未通过真实 VPS 的密钥轮换验收。

## 操作入口

在核验过的源码目录内，经单独授权后运行：

```bash
python3 -m snellctl rotate-key --experimental
```

或者 `python3 -m snellctl menu --experimental`，选择菜单 8。
普通菜单不显示此项，命令不接受 `--yes`、`--force`、自选密钥或秘密参数。

1. 选择仅更换 Snell PSK，或者仅更换 ShadowTLS 密码；不会同时更换两项。
2. 工具从当前受管配置识别实际域名和三个端口，核对归属、版本、运行服务、本机 TLS、续期及防火墙。
3. 保持不依赖本节点的独立 SSH 和恢复控制台可用，另开 SSH 登录并输入“已重连”。
4. 明确输入“更换 Snell”或“更换 ShadowTLS”。其他输入取消；确认后会短暂中断节点连接。
5. 成功后单独运行 `python3 -m snellctl client` 或菜单 5，确认显示新的一整行 Surge 配置。
6. 在 Surge 中更新原节点，测试延迟、诊断下载和实际使用；不要把含密钥配置发送给 AI 或公开分享。

操作前只读检查不是预留：真正更换前会重新加锁、核查现场，
确认期间另一会话已经完成更换或配置发生变化时，本次操作停止。
不要求重新输入域名、端口、Cloudflare Token，也不自动获取公网 IP。

## 修改边界

- 仅生成所选组件的新 256 位随机密钥，不能等于现有任何一项密钥。
- 只替换对应的 root-only 配置文件，并停止、确认停止后再启动对应组件。
  systemd 的 `LoadCredential` 是服务启动时加载的凭据，不能仅改磁盘文件就宣称服务使用了新密钥。
  依据见 [systemd 凭据文档](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#Credentials)。
- 成功路径不重启另一协议组件或 Nginx；不更换二进制、域名、证书、Token、端口，不增删 UFW 规则，不改 SSH。
- 更新 `public-files.json` 和 `public-ready.json` 中所选配置的内容指纹及文件身份。
  初次激活的历史记录不改写，也不能用于回退当前密钥。
- 不显示新密钥、不另存旧密钥备份、不保存第二份完整配置数据库；旧客户端导出副本及终端记录不会被自动销毁。
  不承诺从磁盘、快照、内存或服务管理器中安全擦除历史秘密。
- 不发起 DNS 验证、证书申请或主动续期。正常续期定时器保持原状，可能按自身计划运行。

本机检查验证服务、监听、证书和 TLS 转发，不验证 Snell/ShadowTLS 的实际客户端密码认证。
成功信息明确保留“外部客户端待验收”，不能把 404/TLS 通过等同代理认证成功。

## 失败与中断

写入前创建 root-only 的 `key-rotation-intent.json`，只含组件、参数绑定及内容指纹，
不含域名、IP、明文密钥或 Token。它一直保留到配置、两份当前归属记录、服务和 TLS 检查全部通过。
多个文件与 systemd 操作不是一个原子事务；单文件采用同目录原子替换。

工具捕获到写入阶段失败或中断时，会尝试停止并禁用 ShadowTLS 入口及所选服务，
保留新旧现场和意图，不恢复旧密钥，不重试、不重新签发、不清理候选文件或防火墙规则。
若停止命令本身失败或结果不确定，不能保证入口已关闭。
断电、SIGKILL、SSH 断开导致的未处理终止也可能绕过停用处理，不能宣称断线自动回滚。

存在意图时，新版本的客户端导出、更换操作和公网接续/重复启用都会拒绝继续；
`install-status` 会显示 `key_rotation: needs-inspection`，清理盘点也会提示保留现场。
正常完成后移除此临时意图；`none-pending` 只表示没有待核查标记，不证明服务健康。
当前没有密钥轮换的自动恢复入口。不要删除意图、手动启用服务、运行旧版工具或通过重跑安装绕过它。
保留独立 SSH，先提供脱敏状态，再针对现场决定恢复方法。

## 验收清单

在获授权的测试机逐项进行，每项成功后再进行下一项：

- Snell PSK 更换后另一项密码保持不变，更新 Surge 后实际可用。
- ShadowTLS 密码更换后 Snell PSK 保持不变，更新 Surge 后实际可用。
- 不公开新旧密钥，只反馈成功/失败；原配置失效验证如需执行应单独确认。
- 确认 SSH/UFW、域名/证书/Token、端口及续期定时器未被更换流程改变。
- 正常重启后新配置仍可使用；这不等同断电恢复或所有失败路径验收。

开发测试使用真实临时文件和控制器、模拟系统命令及 TLS 探针进行故障注入，
不在正常 VPS 上制造写盘失败、强杀或密钥认证故障。
