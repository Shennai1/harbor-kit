# 域名资源只读盘点

`domain-inventory --json` 或普通菜单 12，用于本工具完整部署的 main 节点。
这是旧资源清理之前的引用核查，不是卸载器，不提供删除命令。
已取得 Debian 13 / amd64 用户实机反馈：现用及另一组保留证书分别引用独立凭据，有限盘点无异常。
这不扩大为全机引用、历史归属或删除授权已通过。

从已校验的固定版本源码目录执行：

```bash
python3 -E -s -B -m snellctl domain-inventory --json
```

无需输入域名、IP、端口或 Token。不会安装快捷入口，不会联网，不执行系统命令，
不签发或删除证书、不增删 DNS、不重载 Nginx、不停止节点或续期、不修改 SSH/UFW。
报告只输出到终端；不保存新日志或状态文件。

## 检查范围

- 使用已有协作锁，核对 main 的现行归属记录、配置模板、程序摘要与受管续期覆盖文件。
  读取节点配置时密钥会进入进程内存作模板校验，但不输出；不读取 CF 凭据内容、证书私钥内容或日志。
- 枚举固定的 Certbot live/archive/renewal 目录及 snellctl 凭据目录。
  每个目录最多 128 个条目，证书组总数最多 128；超限为不完整，不静默忽略。
- 只检查证书链接指向同组 archive 文件及其元数据，不解析证书内容、不检查有效期或在线 TLS。
- 有界读取续期配置，提取 Cloudflare 凭据引用；绝不打开续期文件指定的外部路径。
  一个凭据可被多个证书组引用，报告保留所有本次已观察到的关联。
- 复查已观察路径的身份、权限、大小和修改时间，并再次核对当前部署。锁只约束本工具的协作操作，
  不能阻止外部 root/Certbot 操作，也不提供全系统原子快照。

## 阅读报告

- 证书组 `current`：现用受管 Nginx 配置和受管续期覆盖文件所引用的证书组。
- 凭据 `current`：当前域名对应的永久凭据路径。
- 各自的 `other-1` 等：本次匿名编号。证书组与凭据的编号不必相同，按照 `credential` 和
  `referenced_by_observed_renewals` 字段判断关联。编号不稳定，不可用作删除参数。
- `collection_complete=true`：在声明的有限范围内收集和结构核对完成，**不是全机引用检查通过**。
- `managed_configuration=disk-references-verified`：现用受管磁盘引用一致，不代表定时器、服务或运行中的证书已检查。
- `partial-preserve-all`：发现超限、不明结构、缺失或异常元数据；全部保留。
- `unverified-preserve-all`：协作锁占用、待核查变更、不可读或扫描中发生改动等原因导致不能核对；不输出半成品关联。
- `cleanup_authorized` 永远是 `false`，资源 `preserve` 永远是 `true`。

其他证书组不能仅凭文件名认领为本工具旧资源。凭据没有出现在本次已读续期配置中，也不能称为无人使用。
其他站点、自定义 Nginx include、计划任务、容器和外部路径仍可能引用它。
不限定证书名的 `certbot renew` 仍可能处理保留的续期配置；本命令不改变这项行为。

退出码：0 表示有限盘点完成，1 表示不完整/未核对，2 表示非 Linux 或不是 root。
JSON 可用于后续核查；不要因此分享原始凭据、节点配置或日志。

原 `cleanup-plan` 仍保持 [元数据盘点](cleanup-inventory.md) 的边界，不读取节点配置或续期文件。
两种报告都不是删除授权。后续清理还需独立范围确认、引用复核及中断保护。
